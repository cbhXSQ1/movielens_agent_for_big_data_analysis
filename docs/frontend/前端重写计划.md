# 前端重写计划（迭代二）

> 状态：已定稿的依据文档。旧前端（原生 HTML/CSS/JS）**整目录弃尽弃**，全部重建。
> 配套：`docs/agent/Agent_接口文档.md`（前端 ↔ Agent 契约；§3.11 资源与文件直通接口）。
> 阅读指引：第 9 节是任务清单，每个任务都标明由哪个子智能体执行，可单独派发。

---

## 1. 技术栈

- **Vue 3 + Vite + TypeScript**
- **Naive UI**（组件库）
- **Pinia**（状态管理）
- **Vitest + Vue Test Utils**（测试）

## 2. 界面结构

```
顶栏：产品名 / 连接状态 / 设置(LLM API)
┌───────────┬────────────────────────────────────────────┐
│ 图标条 ×4  │ 中：结果标签栏（默认只有「对话」；产物出现时才动态加标签）│
│ ①列表 ②树 │ 中：当前标签内容（默认=对话，内嵌结果卡）      │
│ ③资源 ④进度│                                              │
│ 面板(可收起)│                                              │
└───────────┴────────────────────────────────────────────┘
```

- 左栏：顶部图标条 + 面板；**展开推挤中栏、收起只留图标**；**窄屏（≤约 1100px）变抽屉**（默认隐藏，点图标滑出覆盖）。
  - ①**对话列表**：所有对话，可新建 / 切换。
  - ②**对话树**：点开为**悬浮窗**（大画布、横/纵滑块平移、悬停缩略显示该次提问、按钮切到该节点）。
  - ③**资源**：原始数据（`.dat`/`.zip` 上传）｜清洗后数据（已发布版本）｜方案文件（`.json` 上传）｜产出文件（下载/预览）。
  - ④**任务进度**：双编号（Agent 编号 + Hadoop 编号、名称、概括、进度、预计时长）。
- 中栏：结果视图标签栏；对话里的结果以**内嵌卡片**出现，点开切到对应标签全屏看。

## 3. 分层与数据流

- **数据层**：REST（对话管理 / 资源 / 文件 / 上传）+ **每对话一条 SSE 流**（`EventSource`，按事件类型分发，含心跳与断线重连）。
- **状态（Pinia）**：对话、节点树、消息、工具表、任务、资源（数据/方案/文件）、设置、连接。
- **事件**（见接口文档 §3.6）：`tools_snapshot` / `message_delta` / `message_done` / `task_status` / `task_resumed` / `result_payload` / `node_added` / `error`。
- **模式**：`llm`（大模型主控）与 `offline`（离线直调，按工具表渲染参数表单）。

## 4. 结果标签（中栏）· 动态

中栏标签**默认只有「对话」**；当回合产生**产物**（`artifact_added` / `GET …/artifacts`）时，
在对话里以**超链接**呈现，点击**新增一个标签**（**每个文件一个标签**，标签名用 `artifact.title`），
标签内**查看文件内容或下载**。「依据」也是动态产物（随任务附上方案引用）。

- 产物来源：`source=task_file`（任务产物，如 report.md / metrics/*.json / cleaned/*.dat）与 `source=scheme`（依据，方案）。
- 呈现按 `kind`：md→Markdown、json→美化 JSON、text→纯文本、dat/other→下载、scheme→依据渲染。
- 标签**按对话隔离**，切换对话时随该对话的产物变化，刷新后由 `GET …/artifacts` 恢复。

## 5. 评分依据

**从 Agent 取方案内容**（`GET /api/schemes/content?name=…`），不再同源读 `config/*.json`。

## 6. 构建与启动

- 开发：`npm run dev`（Vite 开发服务器）。
- 演示/部署：`npm run build` → `dist/` 静态产物，用静态服务器托管；**接口基址可配置**（默认 `http://localhost:8765`，后端已开 CORS）。
- 测试：`npm run test`（Vitest）。

## 7. 与后端的对接约定

- 全部走 `docs/agent/Agent_接口文档.md` 的 §3（含 §3.11 资源直通）；**不依赖任何已废弃字段**。
- 上传**不经大模型**；资源/文件为直通接口。
- 资源已由后端实现（§3.11）；本前端只消费。

## 10. 实施顺序与并行

- **串行主干**：A → B → C → D → E。
- **可并行**：F（对话树）、G（资源）、H（进度）、I（依据）在 C、B 完成后可并行推进。
- **贯穿**：测试随阶段同步推进，不留到最后。
- 每完成一个任务即可单独提交；不引入未在计划中的依赖。

## 11. 测试策略

- 一律以**假 SSE 流**与假后端驱动组件/ store 测试，不依赖真实服务。
- 覆盖：事件分发与流式拼接、资源上传与错误码、结果块渲染、对话树切换。
- 关键路径要有**正向断言**（正常路径确实生效），不仅测拦截。

## 12. 明确不做 / 已知边界

- 不做前端离线包/CDN 依赖（构建产物自包含）。
- 对话树若极端大，仍以滑块平移为主，不做自动布局寻路。
- 预测（迭代二分类）标签先留位，数据来自后续任务结果。

## 13. 完成定义（DoD）

- `npm run build` 产出 `dist/` 可被静态托管；`npm run test` 全绿。
- 每对话一条 SSE 流，八类事件正确驱动界面；流式打字机与收尾一致。
- 左栏四图标可用、可收起/推挤、窄屏变抽屉；中栏六类结果标签可切。
- 对话树浮窗可平移、悬停缩略、切节点。
- 资源页四段可用，上传（`.dat/.zip`、`.json`）与下载/预览走 §3.11 直通接口。
- 任务进度显示双编号；评分依据来自 Agent 接口。
- 不依赖任何已废弃字段（`intent`/`intent_cn`/旧扁平结果信封/`fallback`·`always`）。
