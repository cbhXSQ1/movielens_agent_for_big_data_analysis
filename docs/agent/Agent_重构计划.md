# Agent 重构计划（迭代二）

> 状态：初稿。本文只覆盖 Agent 这一部分（前端与 Hadoop 侧各有单独文档）。
> 配套文档：`Agent_接口文档.md`（前端↔Agent 契约、Agent↔Hadoop MCP 预留要求）。
> 总原则：行为可解释、结果不编造、数字有来源、小步提交；出问题靠版本历史回退，不为此设计中间态。
> 阅读指引：第 7 节是任务清单，每个任务都标明由哪个子智能体执行，可单独派发。

---

## 1. 目标

把 Agent 重做成一个常驻、可流式、可持久化、可被长任务完成事件唤醒续跑的 **LLM 主控 Agent**，同时保留一条不经模型的「按工具名直调」通道；对话以**树**的形式保存并可回溯。

## 2. 范围与约束

- **只做 Agent**；用接口契约对接前端；**预留 MCP 接口**，Hadoop 侧本次不实现。
- 单用户；对话持久化到磁盘。
- 不受早期约束文档束缚；不保留「零依赖、离线、结果确定」的旧限制。
- LLM 主控为默认；模型不可用**直接报错**。

## 3. 已定决策

- 运行时用 **LangGraph**；工具、策略、护栏、离线直调自建。
- 两种接入模式：**离线直调**（工具名 + 可选参数，缺省填默认值）与 **LLM 主控**。
- 每段对话一条推送流；长任务挂起 → 完成后发「中断」唤醒循环 → 模型续写；全链异步。
- **纯规则意图解析全部删除，不留。**
- 前端可见：任务**编号、名称、概括描述、进度**。
- 结果呈现：**LLM 口头讲解** + **独立板块的结构化结果**（不设优先级，一次给全）。
- 工具表由 Agent **主动推送**（连接时一次 + 变化时再推）。
- **对话树**：可分支、可跳回某节点继续，**旧分支保留**（git 式）。
- **任务编号双轨**：Agent 自生成对话侧编号；Hadoop 侧编号由其回传并保存，供查询使用。

```
┌────────────────────────── 宿主机 ──────────────────────────┐
│  前端（另文档）                                            │
```

## 5. 现有 agent 目录处置

依据逐文件审查（只读）：

| 现有部分 | 处置 | 说明 |
|---|---|---|
| 工具实现（11 个工具）、工具表、策略、中文解释、模型配置、命令行入口 | **保留/扩展** | 确定性能力与护栏，正是要自己握住的 |
| 调用边界（driver 调用层） | **改造** | 全模块唯一跨到 Hadoop 的边界，做成 MCP 接缝；拆除「同机」假设 |
| 中文解释 | **改造** | 支持分块/事件化以配合流式 |
| 模型循环 | **重写为 LangGraph** | 抽取其数字护栏、双协议解析、策略前置、任务判定为独立件后替换 |
| 模型客户端 | **改造** | 现全为非流式，需补流式 |
| HTTP 服务 | **重写** | 现为一次性响应、无对话生命周期；信封/CORS/编码容错可留 |
| 口径快照（session） | **删除/并入** | 被对话持久化取代 |
| 纯规则意图解析 | **删除** | 新方向明确删除 |
| 规则优先入口 | **重写** | 整条分派链是规则意图的消费者；仅信封形状与自检思路可借鉴 |
| 一次性 LLM 增强 | **部分删除** | 输入侧解析删；润色护栏思想并入新护栏 |
| 测试：工具表、策略 | **保留** | 仍有效（注意硬编码计数） |
| 测试：模型循环 | **部分迁移** | 双协议解析与数字护栏用例可迁，其余作废 |

**删除规则意图的连带影响（必须一并处理）**：① 规则优先入口的整条分派（等于重写入口）；② HTTP 服务里回退分支的判据；③ 一次性 LLM 增强输入侧对意图常量的依赖。相关常量需**疏散到新家**。

> **T2.5 执行记录（已删除，不留）**：删除 `agent/intent.py`、`agent/agent.py`、
> `agent/llm_parse.py`；`http_api.py` 的自然语言入口只走 LLM 循环，模型不可用时
> 结构化报错（不回退规则），规则判据 `_needs_start` 一并删除。旧规则入口里值得
> 保留的两点思路记录于此、不保留旧逻辑：① **统一返回信封形状**——`ok / intent /
> intent_cn / reply / error / data / task_id / task_started / opts / engine / llm`，
> 新循环与接口层继续沿用同一形状；② **发起任务前的默认方案自检**——用户明说"用
> 默认规则"时先跑一次 `tools.validate_config`，不过就不发任务，已归到工具/策略层
> 承担。`llm_loop.py`、`session.py` 暂留（阶段 3 替换）。

**一并清除的死代码/死参数**：循环的上下文形参从未被使用；规则解析的置信度与命中词无人消费；策略的「原始数据可读」在真实路径从不设置；轮询组合函数全库无调用；`mode` 的 fallback/always 已死；私有函数被跨模块引用。

## 8. 实施顺序与并行

- **串行主干**：阶段 0 → 1 → 2 → 3 → 4 → 5 → 6。
- **可并行**：阶段 7（对话树）与阶段 6 末段可并行；阶段 8 与阶段 6、7 并行。
- **贯穿**：测试随每个阶段同步推进，不留到最后。
- 每完成一个任务即独立提交；验收不通过不得进入下一步。

## 9. 测试与验证

- 一律以**假模型**驱动单元测试，不依赖真实网关。
- 每次模型输出记录为**事件**，便于复盘与重放，避免重放分叉。
- 护栏必须有**正向断言**（正常路径确实生效），防止「永远拦、系统变哑」。
- 补当前缺失的测试：执行边界、对话持久化与流式、分支隔离。

## 10. 风险与回退

| 风险 | 对策 |
|---|---|
| 框架在当前环境不可用或行为不符预期 | 阶段 0 先验证；不行则评估更轻的替代并回退到自建运行时 |
| 长任务唤醒与流式输出互相覆盖 | 阶段 3 的异步调度先立规矩，阶段 4 依规实现；测试锁死 |
| 分支/跳回把主上下文弄脏 | 分支只读、血缘独立；TX.5 专测隔离 |
| 数字护栏过度拦截导致系统变哑 | 正向断言 + 回归测试 |
| 删除规则意图时漏改连带 | 先疏散常量、以测试兜底；分步提交 |
| 模型供应商行为差异 | 两供应商共用抽象，各自最小兼容测试 |

## 11. 完成定义（DoD）

- 双模式可用：离线直调与 LLM 主控都能端到端跑通。
- 对话持久化；每对话一条推送流；流式输出正常。
- 长任务可挂起、可在完成后唤醒续写。
- 对话树可分支、可跳回，旧分支保留且不污染主上下文。
- 工具表可主动推送；任务进展（双编号）与结果板块数据齐全。
- 护栏有效且有正向断言；无编造、无静默回退。
- 现有测试全绿或已合理迁移；新增测试覆盖上述能力。
- MCP 接缝形状就绪（Hadoop 侧另行实现）。
