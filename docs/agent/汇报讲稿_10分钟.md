# 第 5 节现场汇报讲稿（约 3 分钟）

> 使用场景：全组 10 分钟汇报，你负责第 5 节（Agent）这一段。
> 括号里是**时间**，按这个节奏讲完约 3 分钟。
> 加粗的是**必须说出口的关键词**，老师按这些点打分。

---

## 开场（15 秒）

> 我负责的是第 5 节，Agent 层。
> 一句话说清楚它的位置：**用户说人话，Hadoop 干活，Agent 是中间那层翻译。**
> 它自己不清洗、不评分——清洗规则在配置文件里，执行引擎在第 4 节的 Hadoop 里。
> Agent 只做三件事：**组织任务、调用工具、把结果翻译成人话。**

---

## 第一段：我做了什么（60 秒）

> Agent 侧一共封装了 **9 个工具**：
>
> - 8 个是跟 Hadoop driver 的正式契约：`发起任务、查状态、取结果、取样本、取报告、列方案、校验配置、列任务`
> - 第 9 个是**附加的演示工具** `quick_clean`，秒级出结果、不经过 Hadoop，**只用于现场演示，不能当正式结果**
>
> 一次完整交互是这样：**发起任务 → 立刻拿到任务 ID → 轮询进度 → 跑完取结果 → 用户追问时取异常样本。**
>
> 底层实现上，Agent 通过命令行调用 Hadoop 侧的 driver，**driver 的 stdout 只输出一个 JSON 信封**，日志走 stderr。这样前端、命令行、Python 调用三种方式拿到的都是同一份数据。

**关键词：9 个工具 / JSON 信封 / 不做数据加工**

---

## 第二段：现场演示（60 秒）

> 我现场跑一遍。任务提交后是**异步**的，立刻返回任务 ID，然后可以看实时进度。
>
> （现场执行）
> ```bash
> python3 -m agent.cli start --exec cluster --tag full
> python3 -m agent.cli status --task-id <id> --explain
> python3 -m agent.cli result  --task-id <id> --explain
> ```
>
> 大家看这几个阶段：`用户表清洗 → 电影表清洗 → 评分表清洗 → 打标 → 清洗前评分 → 清洗后评分 → 汇总 → 发布 → 完成`，一共 **9 个阶段**（另有 1 个 `queued` 起始状态，不计入）。
> 这是**真 Hadoop 集群**在跑，Hadoop Streaming + Python，跑完 **10 分钟**。

> 💡 **如果想展示"系统能听懂人话"（强烈建议，秒级出结果）**：
> ```bash
> curl -X POST http://localhost:8765/api/chat \
>      -H 'Content-Type: application/json' \
>      -d '{"text":"任务 20260925-184303-379a4b 跑到哪一步了"}'
> ```
> 返回里的 **`intent_cn": "查询任务执行进度"`** 就是系统自述"我理解你要干什么"。
> 这是作业要求的「系统应理解用户目标」的直接证据，**比讲十句话都管用**。

> ⚠️ **现场风险提示**：全量跑要 10 分钟，现场别真跑。
> 直接展示**已经跑好的那个任务**的结果（task_id `20260925-184303-379a4b`），
> 或者用 `quick_clean --sample 2000` 演示秒级出结果。

## 第四段：诚实口径（30 秒）⭐ 最重要

> 这里我要特别说明一点，也是我们组一致强调的：
>
> **分数提升不等于问题被修好了。**
> 一致性涨了 10.35 分、唯一性涨了 9.1 分，**很大一部分来自把无法判定的记录移出了分母**，不是把它们修对了。
> 所以我们的报告**必须同屏展示两个东西**：一是分数，二是数据量变化和隔离数量。
>
> 另外三条局限也都在报告里原样保留：
> 用户属性是自愿填写未核验的；时效性以数据集发布语境衡量；隔离只统计隔离类规则，去重要单列。

**关键词：隔离 ≠ 修复｜同屏展示数据量与隔离**

## 第四段·可选：大模型增强（30 秒，时间够就讲 / 老师问了就展开）

> 关于「理解用户目标」，我们除了规则解析，还做了一层**可选的大模型增强**，
> 但**默认是关闭的**。
>
> 它只被允许做两件事：一是帮你把这句话理解成系统调用，二是把结果说得更顺。
> **清洗规则永远来自配置文件，分数永远来自 Hadoop 的真实运行**——
> 它既不生成规则，也不碰任何一个数字。
>
> 我们做了三层防护保证它编不了数：数字那段文本**根本不传给它**；
> 就算润色也先换成占位符，它眼里没数字；回来还要过四道校验，
> 不过就**直接丢弃、返回原句**。
>
> 最关键的是：**没配置、没网、或者接口报错，它会自动回落到规则解析，功能一点不降级。**
> 现场我可以把网线拔了，追问照样有结果。

**关键词：默认关闭｜不碰数字｜三层护栏｜自动回落不降级**

## 收尾（10 秒）

> 最后，Agent 层还有一条硬规矩：**不编造**。
> 任务失败或者没跑完时，系统**拒绝返回结果**，只给状态和原因，绝不用上一次的旧数字顶替。
> 我这边给前端的接口文档里也写了这条，是我们三节共同的红线。

# 老师可能问的问题（提前背一下）

| 问题 | 怎么答 |
|---|---|
| **你的 Agent 跟 Hadoop 什么关系？** | 我不做计算。清洗规则在 `config/*.json`，执行在 Hadoop。Agent 负责组织任务、调用、解释。规则全部从配置读，**代码里没写死任何阈值**。 |
| **为什么用 Streaming + Python，不用 Java？** | 组里没有 Maven/Java 构建环境，Streaming 让我们直接用 Python 写 mapper/reducer，开发与调试成本低，作业逻辑一样跑在 YARN 上。 |
| **单机伪分布式也算大数据处理吗？** | 课程环境下是单机验证，但链路是完整的：HDFS 存数据、YARN 调度、MapReduce 计算、多趟作业串联、按版本发布。规模受限于单机资源，**架构是可横向扩展的**。 |
| **你怎么保证结果可复现？** | 三个版本锁死：`data_version` + `rule_version` + `scoring_scheme_version` 写进任务元数据，配置文件算了 sha256。发布目录**不可覆盖**，内容哈希不一致会直接报版本冲突。 |
| **清洗前后分数凭什么可比？** | 用的是**同一份评分方案**（同一版本、同一 sha256），换版本分数就不可比，这一点写进了约定。 |
| **你遇到最大的坑是什么？** | 集群跑不通：`hadoop-env.sh` 里写死了别人机器的绝对路径，driver 又硬编码读它，导致 `hdfs` 命令起不来。**最后靠手动复现命令、看真实报错才定位到**——这也说明"失败时给真实原因"有多重要。 |
| **失败的时候系统怎么表现？** | 拒绝返回结果，返回错误码和真实原因（比如 `TASK_NOT_FINISHED`、`TASK_FAILED` + 失败阶段）。**不会给占位数字**。 |
| **你给前端留了什么？** | 一份对接文档 + 一个零依赖的 HTTP 服务（`python3 -m agent.http_api`），**11 个端点**，带 CORS。主入口是 **`POST /api/chat`**——用户说人话进去，直接返回意图识别 + 结果，一次提示闭环。**前端已于 9/28 全部接上跑通。** |
| **「系统应理解用户目标」体现在哪？** | `agent/intent.py` 做规则式意图解析（9 种意图），返回 `intent_cn` 明说"我理解成什么"，前端直接展示。**解析在 Agent 层完成，不是前端替用户选按钮**。规则之外还有一层**可选的大模型增强**（默认关闭），两条路径共用同一个解析器接口。 |
| **你们接大模型了吗？** | 接了，但做成**可选层、默认关闭**。它只做两件事：帮你把话理解成调用、把结果说得更顺。**规则永远来自 `config/*.json`，分数永远来自 Hadoop 真实运行**，大模型既不生成规则也不碰数字。没配、没网、报错，都自动回落规则，**功能一点不降级**——现场可以拔网线演示。 |
| **为什么规则匹配也算"理解用户目标"？** | 实验资料第 95 行写的是「**系统的具体实现方式由学生自主设计**」，六条要求里没有一条要求必须上大模型。规则实现有三个好处：**离线可跑**（机房没网照样演示）、**结果可复现**（同样的话一定得到同样的调用）、**可解释**（意图表就是一张 Python 字典）。 |
| **大模型会不会编数字？**（必问，答好是加分） | 代码层面做了三层，不是靠提示词"请你别编"：**第一层结构性隔离**——页面上所有数字都是 `explain` 模块拼的，那段文本**物理上根本不传给它**；**第二层占位符模板**——润色前先把数字换成 `{v0}{v1}`，它眼里没数字，回来我们回填原值；**第三层输出后校验**——占位符对不上、出现任何新数字、出现"修复了"这类措辞、长度超标，四条任一不过就**丢弃润色、返回原句**。所以无论它怎么抽风，你看到的数字一定是 Hadoop 跑出来的。 |
| **追问时口径会不会变？**（自己发现的 bug） | 会，我们已经修了。联调时发现：页面选「本地引擎」发起，追问"跑到哪一步了"，driver 却收到了默认的集群口径。根因是追问路径没把执行口径回传。修的时候权衡了三种方案，最后选**按 task_id 记服务端口径快照**——追问本来就带 task_id，所以**不用改前端就能修**，后端也不引入 session 概念；同时把生效口径放进返回体回显，前端想显式回传随时能用。 |
| **为什么不用 requests / openai sdk？** | 我们第 5 节是**零第三方依赖**，全用 Python 标准库，机房离线也能跑。接大模型坚持用标准库 `urllib` 自己实现 HTTP 调用——引一个 pip 包，就把"离线可跑"这个优势一次性丢掉了。 |
| **`quick_clean` 跟正式结果什么区别？** | 附加工具，**同引擎同数**，但不维护任务状态、不做发布和版本保护。只用于演示和快速取数，**权威结果永远是集群任务的 start + result**。 |
| **你那两条红线前端真的做到了吗？** | 做到了，而且已经联调验证：任务没跑完时前端**保持空态、一个数字都不显示**，指标缺失显示「本次未产出」而不是 0；清洗结果页**顶部常驻"隔离≠修复"提示条**，修复/去重/隔离是**三张独立卡片，绝不合并**。 |

# 现场演示备选（怕翻车就用这些）

| 场景 | 命令 | 耗时 |
|---|---|---|
| 展示已跑好的真实结果 | `python3 -m agent.cli result --task-id 20260925-184303-379a4b --explain` | 秒级 |
| 演示秒级清洗 | `python3 -m agent.cli quick-clean --sample 2000` | 几秒 |
| 看几条被隔离的脏数据 | `python3 -m agent.cli samples --task-id ... --type quarantine --table ratings --n 5 --explain` | 秒级 |
| **拔网线演示大模型回落** ⭐ | 先配好大模型 → 说一句规则听不懂的话 → 拔网线 → 再问一次，照样出结果，返回里 `engine` 仍是 `rules`、`note` 写明回落原因 | 秒级 |
| 演示追问不丢口径 | 第一轮带 `{"exec_mode":"local","scope":"sample"}` 发起 → 第二轮**一个参数都不传**只给 `task_id` → 返回 `opts` 里仍然是 local+sample | 秒级 |

**最后一条特别适合现场讲**——能让老师直观看到"脏数据长什么样、为什么被隔离"。

**「拔网线演示回落」是最能加分的一条**：它同时证明了
① 我们确实接了大模型；② 我们没被它绑架；③ 规则路径是真的能独立跑通的。
