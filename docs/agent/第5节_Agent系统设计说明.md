## 一、本节要解决的问题

用户只会说人话（"帮我把这份数据洗干净，告诉我质量怎么样"），
但真正干活的是 Hadoop。中间缺一层"翻译"：

- **往下**：把人的意图变成一条条 Hadoop 任务，并盯着它跑
- **往上**：把 Hadoop 吐回来的 JSON 数字翻译成人能读懂的结论

第 5 节（Agent）做的就是这一层。**它自己不做任何数据加工**：
清洗规则在 `config/cleaning_rules.v1.json`，评分公式在 `config/scoring_scheme.v1.json`，
执行引擎在 `hadoop/`（第 4 节）。Agent 只负责**组织、调用、解释**。

## 二、系统结构

```
用户（自然语言）
      │
      ▼
┌─────────────────────────────────────────┐
│  第 6 节 前端：问题输入 / 状态 / 五维对比  │
└─────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────┐
│  第 5 节 Agent（本节）                    │
│   tools.py      9 个工具                 │
│   explain.py    数字 → 中文              │
│   driver_client.py  调 CLI / 解析信封     │
│   session.py    运行口径快照（追问沿用）   │
│   ┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈ │
│   llm_*.py      大模型可选层（默认关闭）   │ ← 虚线：不配置则完全不存在
└─────────────────────────────────────────┘
      │ python3 hadoop/driver/run_task.py <子命令>
      │ stdout：单个 JSON 信封；stderr：日志
      ▼
┌─────────────────────────────────────────┐
│  第 4 节 Hadoop：清洗 + 五维评分 + 发布    │
│   Streaming + Python，伪分布式单机         │
└─────────────────────────────────────────┘
```

**部署**：Hadoop、driver、Agent 同在一台 Ubuntu 虚拟机内，
任务产物落在 `<repo>/var/tasks/<task_id>/`，两边共享同一份目录。

## 三、9 个 Agent 工具

8 个来自接口契约（`docs/hadoop/agent-interface.md` v1.0 §7），1 个是附加工具。

| # | 工具 | 调 driver | 作用 |
|---|---|---|---|
| 1 | `validate_config(rules?, scoring?)` | `validate` | 校验清洗/评分方案是否合法 |
| 2 | `list_schemes()` | `schemes` | 列出已登记方案 |
| 3 | `start_cleaning_task(...)` | `start` | 发起清洗+评分任务，立即返回 task_id |
| 4 | `get_task_status(task_id)` | `status` | 查阶段与进度百分比 |
| 5 | `get_task_result(task_id)` | `result` | 取权威结果（五维对比 / 数据量 / 隔离） |
| 6 | `get_samples(task_id, type, table, n)` | `samples` | 取清洗后或隔离区样例 |
| 7 | `get_report(task_id, format)` | `report` | 取完整评估报告（md / json） |
| 8 | `list_tasks()` | `tasks` | 列出最近 50 个任务 |
| 9 | `quick_clean_demo(...)` | **附加** `quick_clean` | 秒级演示性清洗，不经 Hadoop |

**第 9 个不属于 v1.0 契约子命令集。** 它与集群任务同引擎同数，
但不维护任务状态、不做发布与版本冲突保护，**只用于现场演示与快速取数**。
对外汇报的权威数字一律来自 `start_cleaning_task` + `get_task_result`。

### 附：自然语言入口（`/api/chat`）

9 个工具之上有**一个自然语言入口**，由 `agent/intent.py` + `agent/agent.py` 实现：

```
用户原话 → 规则式意图解析（9 种意图 + 参数抽取）→ 调对应工具 → 结果 + 中文解释
```

返回 `intent_cn`（系统自述"理解成什么"），供前端展示，证明意图是被识别的。
**解析在第 5 节完成，前端不做解析。**

| intent | 含义 |
|---|---|
| `clean_evaluate` | 发起清洗 + 五维评估 |
| `task_status` / `task_result` | 查进度 / 取结果 |
| `get_samples` / `get_report` | 取样本 / 取报告 |
| `list_schemes` / `list_tasks` | 方案列表 / 任务列表 |
| `quick_demo` | 快速演示（不经 Hadoop） |
| `help` / `unknown` | 查看可用说法 / 未识别（如实提示，不猜） |

共 9 种意图 + `unknown`，规则集中在 `agent/intent.py` 的 `KEYWORDS` / `PATTERNS` 表，
扩展说法只改表。匹配有优先级（先具体后笼统），避免"结果"同时命中两个意图。

### 一次完整交互

```
1) start       → 拿到 task_id，先告诉用户"任务已提交"
2) status      → 轮询，展示进度（如 第 3/9 步、33%、clean_ratings）
3) result      → 成功后给五维对比 + 数据量变化 + 隔离统计 + 局限性
4) samples     → 用户追问"给我看几条异常记录"时用
5) report      → 输出完整评估报告
```

## 四、三条设计红线

### 1. 不编造

任务失败或未完成时，driver 会**拒绝返回结果**（退出码 3 / 5）。
Agent 拿到错误信封后**原样转述**，绝不用上一轮的旧数字或占位值冒充成功。

代码层面：driver 的 stdout 只允许有一个 JSON 信封，解析不出来就报
`DRIVER_BAD_OUTPUT` / `DRIVER_NO_OUTPUT`，不猜、不补。

### 2. 隔离 ≠ 修复

被隔离的行是**移出正表**，不是被修好了。分数提升有一部分是"把问题行挪出分母"带来的。
因此 `explain_result` 每次输出都**强制同屏包含三块**：

1. 数据量变化（输入 → 输出）
2. 隔离 / 去重 / 修复 各自的条数
3. `limitations`（系统自带的局限性说明）

并在结尾固定附一句口径提醒。

### 3. 配置只读

清洗规则与评分方案全部从 `config/*.json` 读取，Agent 代码里**不硬编码任何规则或阈值**。
版本三元组 `(data_version, rule_version, scoring_scheme_version)` 写进每次任务的元数据，
保证清洗前后用的是同一套评分口径，否则分数不可比。

### 附：大模型可选层的三条额外约束（默认关闭，不配置则完全不存在）

官方实验资料第 95 行写明「系统的具体实现方式由学生自主设计」，
**并未要求接入大模型**。我们把它做成**可选增强层**，并给自己加了三条硬约束：

1. **只做两件事**：① 输入侧的意图/参数理解；② 输出侧的措辞润色。
2. **不生成规则、不碰数字**：规则永远来自 `config/*.json`
   （`cleaning_rules.v1.json` 明写「禁止 LLM 现编逻辑」）；
   分数/行数/隔离数 100% 来自 driver 的真实结果。
3. **不可用就如实回落**：没配置、没网络、超时、返回不合法，
   一律回落到规则解析，并在返回体的 `llm.note` 里写明**真实原因**，功能不降级。

防编造做了三层（详见 `agent/llm_parse.py` 文件头注释）：
结构性隔离（数字文本根本不传给它）→ 占位符模板（它眼里没数字）→
输出后四道校验（不过就丢弃润色、返回原句）。

## 五、运行方式

```bash
cd ~/movieLens-agent

# 提交任务（后台异步，立即返回 task_id）
python3 -m agent.cli start --exec cluster --tag full

# 联调想快一点：本地引擎 + 样本口径（几十秒，但数字不可用于汇报）
python3 -m agent.cli start --exec local --scope sample --foreground --tag selftest

# 查进度
python3 -m agent.cli status --task-id <id> --explain

# 取结果（带中文解释）
python3 -m agent.cli result  --task-id <id> --explain

# 看被隔离的脏数据长什么样
python3 -m agent.cli samples --task-id <id> --type quarantine --table ratings --n 5 --explain
```

> ✅ **不用再带 `ML_FULL_RUN=1`**。driver 自 D-016 起默认就是**全量**
> （`start --scope full|sample`，默认 `full`），约 8 分钟。
> 只有联调想快一点才显式写 `--scope sample`（只抽 2000 行，数字不可用于汇报）。
> 旧命令里带 `ML_FULL_RUN=1` 也不会报错（环境变量保留但已无实际作用）。

| 项 | 值 |
|---|---|
| rule_version | 1.0.0 |
| scoring_scheme_version | 1.0.0 |
| operator_library | ml1m-ops.v1 |
| T1 / T2 | 2001-12-31T23:59:59Z ／ 2002-06-30T23:59:59Z |
| 发布路径 | `/data/published/ml1m-clean-v1` |

清洗前后使用**同一份评分方案**（`scoring_scheme.v1.json` 的 sha256 一致），否则分数不可比。

### 6.5 一处值得单独说的诚实做法

driver 输出的 `rule_notes` 主动列出了 **4 条配置里"人写的备注"和"代码实际执行的判断"对不上**的规则
（U2 / U3 / M8 / R9），并把两套数字并列说明差异原因，同时声明"以 `detect` 为准"。

这 4 处都属于 `fix` 或 `mark_only`，**不影响** counts 与 36 个指标值。
这种做法本身就是"不编造"原则的体现——**发现口径不一致就摆出来，而不是悄悄改掉**。
汇报时值得提一句，是加分项。

## 七、已知限制（如实说明）

1. **用户属性未核验**：MovieLens 的年龄、职业等为自愿填写，A3 / C1 等指标不封顶是诚实口径。
2. **部分提升来自隔离而非修复**：如 U3 / S4 的提升，详见报告正文。
3. **时效性以数据集发布语境评估**：若用现实时间衡量必然过时。
4. **自然语言解析以规则式为主，大模型只是可选增强**：本节已实现 `agent/intent.py`，
   把用户原话映射到「调哪个工具 + 什么参数」，共 9 种意图（见 §三·附）。
   **解析归第 5 节，第 6 节前端只负责展示 `intent_cn`，不做任何解析。**
   局限：只覆盖预置表述，生僻说法会如实提示可用表达，**不做猜测**。
   规则之外另有一层大模型可选增强（默认关闭），只在规则没把握时才介入，
   且**不生成规则、不产出数字**——详见 §四·附。
5. **单机伪分布式**：Hadoop 跑在一台虚拟机上，不具备横向扩展能力。
6. **口径快照存在于内存**：`agent/session.py` 按 task_id 记住运行口径，
   **进程重启后失效**并回落到 driver 默认值（`cluster` + `full`）——失效方向是安全的。
