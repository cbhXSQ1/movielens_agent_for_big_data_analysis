## 一、本节定位（一句话）

**用户说人话，Hadoop 干活，Agent 是中间那层翻译。**

- 第 4 节（Hadoop）负责真正的数据清洗与评分计算
- 第 6 节（前端）负责页面展示
- **第 5 节（本节）负责：把用户的一句自然语言变成一次 Hadoop 任务，再把跑出来的数字翻译成人能读懂的结论**

本节**自己不做任何数据加工**。清洗规则在 `config/cleaning_rules.v1.json`，
评分方案在 `config/scoring_scheme.v1.json`，执行引擎在第 4 节的 Hadoop 里。
Agent 里**没有写死任何规则或阈值**。

## 二、做了什么

### 1）9 个 Agent 工具

| # | 工具 | 作用 |
|---|---|---|
| 1 | `start_cleaning_task` | 发起清洗 + 评分任务（异步，立即返回任务 ID） |
| 2 | `get_task_status` | 查执行进度（9 个阶段、百分比） |
| 3 | `get_task_result` | 取权威结果 |
| 4 | `get_samples` | 取清洗后 / 隔离区样例 |
| 5 | `get_report` | 取完整评估报告 |
| 6 | `list_schemes` | 列出已登记方案 |
| 7 | `validate_config` | 校验配置 |
| 8 | `list_tasks` | 列出历史任务 |
| 9 | `quick_clean_demo` | **附加工具**：秒级演示，不经 Hadoop |

前 8 个是与 Hadoop driver 的正式契约；第 9 个只用于现场演示，
**权威结果永远来自「发起任务 + 取结果」**。

### 2）自然语言意图解析（规则式）

用户直接说人话，Agent 解析成"调哪个工具 + 什么参数"：

```
"用默认规则清洗 MovieLens 1M 并评估五维质量"      → 发起清洗+评估任务
"任务 20260925-184303-379a4b 跑到哪一步了"        → 查进度
"给我看 5 条被隔离的评分记录"                      → 取样本(type=quarantine, table=ratings, n=5)
"出一份完整评估报告"                              → 取报告
```

用**规则匹配**而非大模型：离线可跑、结果确定、便于答辩解释。
规则集中在一张关键词表里，扩展说法只需改表。
**匹配不出来就如实说"没听懂"并给出可用说法，不猜。**

### 3）结果解释（JSON → 中文）

`explain` 模块把 driver 返回的 JSON 翻成人话，并且**每次都强制输出三块**：

1. 数据量变化（输入 → 输出）
2. 隔离 / 去重 / 修复各自的条数
3. 系统自带的局限性说明

结尾固定附一句口径提醒。

## 六、本节遵守的三条红线

1. **不编造**——失败或未完成时，driver 拒绝返回结果，Agent 原样转述原因，绝不用占位数字冒充
2. **隔离 ≠ 修复**——分数提升有一部分来自把问题行移出分母，必须同屏说明
3. **配置只读**——规则全从 `config/*.json` 读；清洗前后用同一份评分方案（同一 sha256），保证可比

---

## 七、已知限制（如实说明）

1. 用户属性为自愿填写、未经核验，部分指标不封顶是诚实口径
2. 时效性以数据集发布语境评估，用现实时间衡量必然过时
3. 单机伪分布式，规模受限于单机资源（架构可横向扩展）
4. 自然语言解析为**规则式**，覆盖常见说法；生僻说法会提示可用表达，不做猜测
5. 端到端"一次提示"闭环需与第 6 节前端联调后完整演示
