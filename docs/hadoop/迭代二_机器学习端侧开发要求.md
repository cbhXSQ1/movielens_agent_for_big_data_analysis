# 迭代二 · Hadoop 端侧机器学习（分类 / 聚类 / 降维）开发要求

> 交付对象：**虚拟机（Hadoop）端开发**。
> 目的：把**分类 / 聚类 / 降维**三类分析能力以 **MCP 工具**对外，供宿主机 Agent 调用；产出模型、画像、群体、坐标、参数、指标与**版本**，供**迭代三**复用。
> 前提：迭代一发布区 `ml1m-clean-v1` 与 **T1/T2** 可用；能力服务（迭代一重构的 `mcpserver/`）已在运行。
> 总原则：**能力加性**（不升契约版本）、**错误语义无损**、**长任务可被唤醒**、**可发现可取证**；**返回字段以本文件为准**（两端并行开发，减少冲突）。

---

## 1. 目标与边界

- 三类任务，**每类两种算法，每种算法一个工具**（共 **6 个训练/评估工具**），另加 **1 个预测工具** 与 **2 个只读查询工具**。
- 计算在**端侧**（数据在发布区）；**与 Hadoop 数据的具体结合方式（读 HDFS / 落地文件、调度、资源）由端侧决定**。
- 保留：**分类模型、用户画像、用户群体、降维模型与坐标、算法参数、评价指标、版本**。

## 2. 数据边界（三类共同）

- **数据源**：发布区 `ml1m-clean-v1` 的 `ratings` / `users` / `movies`；携带 `data_version` 与哈希。
- **时间划分**：训练 ≤ **T1**、验证 **(T1, T2]**、测试 **> T2**（沿用迭代一确定的 T1/T2）。
- **防时间泄漏（红线）**：所有历史统计特征**只用预测时点之前**的数据（点对点构建）；**绝不用验证/测试期信息构造训练输入**。
- **不使用占位/示例/推测数据**；失败如实返回失败环节与原因。

## 3. 工具清单（加性；契约版本沿用 `1.0`）

| 工具 | 任务 | 长耗时 | 说明 |
|---|---|---|---|
| `train_classifier_naive_bayes` | 分类 | 是 | 朴素贝叶斯 |
| `train_classifier_tree` | 分类 | 是 | 树集成（**随机森林**）；若端侧选 **XGBoost**，则命名 `train_classifier_xgboost`，二者**择一**实现 |
| `cluster_kmeans` | 聚类 | 是 | K-Means |
| `cluster_hierarchical` | 聚类 | 是 | 凝聚层次（Ward） |
| `reduce_pca` | 降维 | 是 | PCA |
| `reduce_nmf` | 降维 | 是 | NMF（输入整体平移到非负） |
| `predict_high_rating` | 分类预测 | 否 | 用已存模型预测"某用户对某电影是否 ≥4 分" |
| `list_ml_models` | 只读 | 否 | 列已登记模型/产物 |
| `get_ml_model` | 只读 | 否 | 取某模型的元数据与指标 |

> 训练类工具**一律异步受理、立即返回**（见 §8）；`predict_high_rating` 为同步短调用。

## 4. 输入参数（定死）

**所有训练类工具共有参数：**

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `data_version` | string | 否 | 发布区最新/`ml1m-clean-v1` | 数据版本 |
| `tag` | string | 否 | — | 任务备注 |
| `params` | object | 否 | `{}` | 算法超参（键与默认由端侧定，须回显生效值） |

**算法补充参数：**

| 工具 | 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|---|
| `cluster_kmeans` / `cluster_hierarchical` | `k` | int | 否 | 端侧自选 | 不传时按轮廓系数/肘部选定；**两种聚类使用同一个 k** |
| `reduce_pca` / `reduce_nmf` | `n_components` | int | 否 | 端侧自选 | 目标维度 |
| `predict_high_rating` | `model_id` | string | 是 | — | 分类模型编号 |
| `predict_high_rating` | `user_id` | int/string | 是 | — | 用户 ID |
| `predict_high_rating` | `movie_id` | int/string | 是 | — | 电影 ID |
| `get_ml_model` | `model_id` | string | 是 | — | 模型编号 |

## 5. 返回字段（**定死**；成功信封）

统一外层：`ok`、`interface_version`。以下为业务字段（**按任务类型**）。

### 5.1 训练/评估工具（6 个）共有字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `model_id` | string | 形如 `ml-YYYYMMDD-HHMMSS-xxxx` |
| `task_type` | string | `classification` / `clustering` / `dimensionality_reduction` |
| `algorithm` | string | 如 `naive_bayes` / `random_forest` / `kmeans` / `hierarchical` / `pca` / `nmf` |
| `status` | string | 五态：`queued/running/succeeded/failed/aborted` |
| `data_version` | string | 使用的数据版本 |
| `time_boundaries` | object | `{"T1": <ISO8601>, "T2": <ISO8601>}` |
| `params` | object | **生效**超参（含端侧自选的 `k` / `n_components`） |
| `metrics` | object | 见 5.2 / 5.3 / 5.4 |
| `artifacts` | array | 产物清单：`[{id,title,kind,path,size}]`（kind：`model`/`profile`/`labels`/`coords`/`meta`） |
| `created_at` | string | ISO8601 |

### 5.2 分类 `metrics`

| 字段 | 类型 | 说明 |
|---|---|---|
| `f1` | number | 主指标 |
| `auc` | number | **ROC-AUC**，主指标 |
| `precision` | number | |
| `recall` | number | |
| `pr_auc` | number | 补充指标（正类不平衡） |
| `threshold` | number | 决策阈值（默认 0.5） |
| `confusion_matrix` | object | `{"tp":int,"fp":int,"tn":int,"fn":int}` |
| `positive_rate` | number | 数据里正类比例 |
| `feature_importance` | array | `[{feature, importance}]`（若无则空数组） |

### 5.3 聚类 `metrics`

| 字段 | 类型 | 说明 |
|---|---|---|
| `k` | int | 实际使用的簇数 |
| `silhouette` | number | 轮廓系数 |
| `davies_bouldin` | number | |
| `clusters` | array | `[{cluster_id:int, size:int, label:string, top_genres:[string], behavior:{activity,avg_rating,rating_std,recency}}]` |

> `label` 为**自动生成的中文群体标签**（如"动作/科幻偏好 · 高活跃 · 评分偏严"）。

### 5.4 降维 `metrics`

| 字段 | 类型 | 说明 |
|---|---|---|
| `n_components` | int | 目标维度 |
| `explained_variance_ratio` | array\|null | PCA 专有（NMF 为 null） |
| `reconstruction_error` | number | 重构误差 |
| `resource` | object | `{"fit_seconds":number,"mem_mb":number}` |
| `comparison` | object | **对比实验**：`{"before":{"silhouette":number,"davies_bouldin":number,"k":int},"after":{...},"agreement":{"ari":number,"nmi":number}}` |

> `before` = 全维画像直接聚类；`after` = 降维后再聚类（**同一聚类算法**）；`agreement` 比较两者分组一致性。

### 5.5 `predict_high_rating` 成功返回

| 字段 | 类型 | 说明 |
|---|---|---|
| `model_id` | string | |
| `user_id` / `movie_id` | int/string | 回显 |
| `prediction` | object | `{"label": 0|1, "probability": number, "threshold": number}` |
| `model_version` | string | 模型版本指纹 |

### 5.6 `list_ml_models` 成功返回

`models`：数组，每项 `{model_id, task_type, algorithm, data_version, created_at, metrics_summary:{<关键指标>}}`。

### 5.7 `get_ml_model` 成功返回

`model`：`{model_id, task_type, algorithm, data_version, time_boundaries, params, metrics, artifacts, created_at}`（字段与 5.1 对齐）。

## 6. 落盘与版本（模型文件是什么）

- **模型对象**：sklearn 估计器（朴素贝叶斯、随机森林、KMeans、凝聚层次、PCA、NMF）与其配套**编码/预处理**（OneHot/Ordinal/MultiLabelBinarizer/StandardScaler、NMF 平移 MinMax）→ **joblib** `.joblib`；**XGBoost** → 原生 `.json`/`.ubj`。
- **元数据 sidecar（JSON）**：`model_id`、`task_type`、`algorithm`、超参、训练窗口（≤T1）、`data_version`、特征清单与编码器引用、`metrics`、`created_at`。
- **数据类产物**：每用户群标签（CSV/JSONL）、群体画像（JSON）、降维坐标（CSV/JSONL）。
- **目录与索引**：`var/ml/<model_id>/`（模型 + 元数据 + 产物）；登记到索引，携带**数据版本 + 算法 + 参数指纹**，供迭代三复用。
- **归属**：模型与产物**留在能力服务侧**；Agent 只取结果与产物引用，**不代理、不存储模型**（需要下载时才经下载中转流式过手）。

## 7. 错误语义（复用现有码，加性）

| 场景 | 错误码 |
|---|---|
| 模型编号不存在（预测/取模型） | 建议**加性新增** `MODEL_NOT_FOUND`（附 `model_id`） |
| 发布区版本/表缺失 | `DEPENDENCY_MISSING` |
| 有任务在跑 | `TASK_ALREADY_RUNNING`（附占用者） |
| 参数非法 | `USAGE` |
| 训练失败 | `TASK_FAILED` |
| 等待名额满 | `WAIT_LIMIT_REACHED` |
| 已中止 | `ABORTED` |

> 沿用"先看 `ok`、再看业务字段或 `error`"的信封约定；新码并入 `describe_capabilities.error_codes`。

## 8. 长任务与唤醒

- 训练类工具**异步受理**：立即返回 `model_id`（与任务编号同风格）；进度用现有"查状态 / 等任务结束"机制；状态五态。
- 完成后 Agent 侧唤醒续写；`model_id` 与 `hadoop_task_id` 的对应关系见 Agent 侧接口文档。

## 9. 只读资源（可选，建议实现）

- `ml://models`（列模型）、`ml://model/{model_id}`（模型元数据/指标）。

## 10. 验收标准（VM 侧自测）

1. **工具齐全**：§3 的工具都被 `describe_capabilities` 列出，参数与 §4 一致。
2. **形状正确**：每个工具的成功返回字段与 §5 一致（前端直接消费）。
3. **两算法同口径**：分类两法（NB、树集成）同数据范围、同 T1/T2、同指标；聚类两法同画像、同 k。
4. **防泄漏可核查**：历史特征只用到预测时点之前。
5. **降维对比**：给出"降维前后聚类一致性（ARI/NMI）、信息保留、资源开销"三项。
6. **版本可追溯**：模型与产物有 `model_id`、数据版本、参数指纹、指标。
7. **真数据实跑**：产出真实指标（不得模拟）。
8. **错误如实**：`MODEL_NOT_FOUND` / `DEPENDENCY_MISSING` / `USAGE` 等按 §7 返回。

## 附：算法路径与选择理由（速览）

| 任务 | 算法一 | 算法二 | 理由 |
|---|---|---|---|
| 分类 | 朴素贝叶斯 | 随机森林（备选 XGBoost） | 生成式概率 vs 树集成，机制差异大、兼具可解释与精度 |
| 聚类 | K-Means | 凝聚层次（Ward） | 质心=可解释群体画像；层次=群体结构/树状图 |
| 降维 | PCA | NMF | 方差最大化（线性）vs 部分式分解（可解释"典型口味"） |

**用户偏好画像（聚类与降维的共同输入）**：18 个电影类型偏好占比 + 4 个行为统计（活跃度、均分、评分波动、最近活跃）；仅用训练窗口（≤T1）的评分构建；行内归一化 + 连续维标准化。

## 12. 本端实现说明（2026-10-18，先于开发落定）

> 记录实现前的四项取舍与一处对外契约调整，供三方对齐；与正文冲突处以本节为准。

### 12.1 对外能力收敛为六项（正文为九项）

正文 §3 写的是"每种算法一个工具，共 6 个训练/评估工具"。本端实现时**收敛为"每类一个训练能力、算法由参数选择"**，
理由是：六种算法共享同一条流水线（取数据 → 构造特征 → 训练 → 评估 → 落盘 → 登记），差别只在最后两步；
收敛之后加算法只是加一个枚举值，不必新增能力、不必通知对端改工具表，也避免出现六个名字相近的入口。

| 本端工具 | 覆盖正文里的 | 算法取值 |
|---|---|---|
| `train_classifier` | 朴素贝叶斯 + 树集成 | `naive_bayes` / `random_forest` |
| `cluster_users` | K-Means + 凝聚层次 | `kmeans` / `hierarchical` |
| `reduce_dimensions` | PCA + NMF | `pca` / `nmf` |
| `predict_high_rating` | 同正文 | — |
| `list_ml_models` | 同正文 | — |
| `get_ml_model` | 同正文 | — |

返回字段完全按正文 §5：算法由 `algorithm` 字段回显，任务类型由 `task_type` 回显，前端按这两个值区分展示，与"九个入口"等价。

### 12.2 训练任务并入现有任务体系

- 训练类能力与迭代一重构的清洗任务**共用同一个执行位、同一套状态文件与同一套取消/等待机制**；
  **模型编号即任务编号**（形如 `ml-YYYYMMDD-HHMMSS-xxxx`），因此"查状态 / 等任务结束 / 取消任务 / 查占用状态 / 列任务"无需新增入口。
- 代价：训练期间执行位被占用，此时发起清洗任务会得到"已有任务在运行"并给出占用者 —— 这是刻意的（一次只做一件事，状态与取消才可统一）。
- 模型与产物落在独立目录（`var/ml/<模型编号>/`），任务状态仍落在 `var/tasks/<编号>/`，两者用同一个编号对应。

### 12.3 产物清单的"类型"与"角色"分开

正文 §5.1 的 `artifacts` 里"类型"写的是模型/画像/标签/坐标/元数据（用途）。本端保留既有约定：
**`kind` 一律表示文件格式**（`json` / `joblib` / `csv` / `jsonl` 等），**新增 `role` 表示用途**
（`model` / `profile` / `labels` / `coords` / `meta`）。这样同一字段在全服务含义一致，
前端既能按用途分类，也能按格式判断能否在线预览。正文中的"类型"请按本节的 `role` 理解。

### 12.4 其余三项取舍

| 项 | 决定 | 说明 |
|---|---|---|
| 第二个分类算法 | **随机森林**（工具内固定，不再单列） | 零额外依赖、内存可控；XGBoost 需另装约百兆且内存更高，本机七Ｇ内存下不划算 |
| 模型文件对外 | **新增一条同口径的下载路由**（同一口令、白名单、流式） | 与"任务产物 / 已发布数据"两段下载一致，不把模型塞进调用参数 |
| 超参 `params` | 新增"对象"参数类型；**未知键一律拒绝并列出可用键** | 与现有"未知参数一律报错"一致，避免拼错字按默认值跑出结果 |
| 训练时长 | 单次训练有上限（默认三十分钟），超时按失败如实报告并释放执行位 | 避免一次训练长期占住执行位 |
| 防时间泄漏 | 按时间排序的**前缀聚合**（每个预测时点只用它之前的数据） | 比"用 T1 冻结特征"更严格；实际采用的做法会写进模型元数据 |
| 新错误码 | `MODEL_NOT_FOUND`（附 `model_id`） | 加性，并入能力自描述 |
| 指标单位 | **零到一之间的小数、保留四位**（如 AUC 0.7846） | 与迭代一清洗评分的百分制不同；前端显示百分比时自行乘一百，服务端不做两套 |
| 计算安排 | **单机训练（默认即单机、非分布式，不提交任何集群作业）**，另预留"作业聚合"开关（默认关闭） | 当前数据量（二十四兆、一百万行）下分布式无收益；打开开关后先由一节集群作业算历史统计与抽样，训练读紧凑画像表。量化参考见实现方案 §11 |
