# 迭代二 · 机器学习端侧实现方案

> 依据：`docs/hadoop/迭代二_机器学习端侧开发要求.md`（要求与验收）及其 §12 实现说明（本端已定的四项取舍）。
> 本文只讲**怎么实现**：能力划分、任务模型、数据与特征、产物与目录、分段推进。
> 与要求文档冲突处，以要求文档 §12（本端实现说明）为准。

---

## 1 范围与不做什么

**做**：分类、聚类、降维三类分析能力，各两种算法；一个同步预测；两个只读查询。产出模型、画像、群体、
坐标、指标与版本，供迭代三复用。

**不做**：不引入流式/分布式训练框架（数据只有二十四兆，单机足够）；不做模型在线服务化；不替对端做展示。
训练、评估、预测全部在虚拟机端侧完成，模型**留在端侧**。

---

## 2 能力清单（六项，加性，契约版本仍为 1.0）

| 工具 | 类型 | 参数 | 说明 |
|---|---|---|---|
| `train_classifier` | 长任务 | 共有参数 + `algorithm`（`naive_bayes` / `random_forest`） | 预测"某用户对某电影是否 ≥4 分" |
| `cluster_users` | 长任务 | 共有参数 + `algorithm`（`kmeans` / `hierarchical`）+ `k`（可选） | 用户偏好画像聚类，两算法共用同一个 k |
| `reduce_dimensions` | 长任务 | 共有参数 + `algorithm`（`pca` / `nmf`）+ `n_components`（可选） | 降维，并给出"降维前后聚类一致性"对比 |
| `predict_high_rating` | 同步短调用 | `model_id`、`user_id`、`movie_id` | 用已存分类模型预测 |
| `list_ml_models` | 只读 | — | 列已登记模型 |
| `get_ml_model` | 只读 | `model_id` | 取模型元数据与指标 |

**共有参数**：`data_version`（缺省取发布区当前版本）、`tag`、`params`（算法超参对象，未知键拒绝并列出可用键）。

**与要求文档的差异**：要求文档把六种算法写成六个独立工具；本端收敛为"每类一个、算法用参数选"，
理由见要求文档 §12.1。返回字段仍按要求文档 §5，`task_type` 与 `algorithm` 回显，前端按这两个值区分。

## 3 契约层增补

| 增补 | 内容 |
|---|---|
| 参数类型 | 新增"对象"类型（超参字典）；未知键一律拒绝并列出可用键；协议层会把对象原样传递 |
| 错误码 | 新增 `MODEL_NOT_FOUND`（附 `model_id`）；其余复用既有码（`DEPENDENCY_MISSING` / `TASK_ALREADY_RUNNING` / `USAGE` / `TASK_FAILED` / `WAIT_LIMIT_REACHED` / `ABORTED`） |
| 产物字段 | `kind` 仍表示文件格式；**新增 `role`** 表示用途（`model` / `profile` / `labels` / `coords` / `meta`） |
| 状态取值 | 沿用五态（含"已中止"），训练任务与清洗任务同一套 |

## 4 任务模型：并入现有体系

- **模型编号即任务编号**（`ml-YYYYMMDD-HHMMSS-xxxx`）。训练受理后写与清洗任务**同构的状态文件**于
  `var/tasks/<编号>/status.json`（含 `task_type`、`stage`、`stage_index/total`、`progress_percent`、
  `params`、`errors`）。因此"查状态、等任务结束、取消、查占用状态、列任务"**无需新增入口**。
- **执行位共用**：训练占用同一个执行位；期间发起清洗任务会得到 `TASK_ALREADY_RUNNING` 并给出占用者。
  这是刻意的（一次只做一件事，状态与取消才能统一）。
- **阶段划分**（训练任务，用于进度展示）：
  `queued → load_data → build_features → train → evaluate → persist → register → done`
  （分类多一步 `predict_split` 评估；聚类多一步 `profile`；降维多一步 `compare`）。降维的 `compare` 需要
  在降维前后各聚一次类，属真实计算，如实计入耗时。
- **取消**：沿用既有中止机制（中止请求标记 + 进程组信号 + 状态守卫），训练进程被杀后释放执行位。
- **超时**：单次训练上限默认三十分钟；超时按失败如实报告（阶段与原因），并释放执行位。

## 5 数据与特征

- **数据源**：发布区 `ml1m-clean-v1`（`ratings` / `users` / `movies`）。训练前把三表取到本机缓存目录
  （按数据版本 + 内容清单哈希缓存，命中即复用），**不重复从集群拉**。
- **时间划分**：训练 ≤ T1、验证 (T1, T2]、测试 > T2；T1/T2 取自发布数据对应的方案声明，并写入模型元数据。
- **防时间泄漏（红线的落地方式）**：按时间戳排序后做**前缀聚合**——每条样本的"历史统计特征"只由**它之前**
  的时间戳聚合而来（用户历史均分/活跃度、电影历史均分/热度）。实现上按用户、电影各做一次累积聚合，
  样本按时间顺序消费；不使用验证/测试期信息构造任何训练输入。实际做法写进模型元数据（`feature_spec.leakage`）。
- **分类特征**（4～6 个，含类别与数值）：性别、年龄、职业（独热）、类型（多热）、电影历史均分、电影热度、
  用户历史均分、用户活跃度。编码器随模型一起落盘，未知类别忽略。
- **聚类与降维的输入**：用户偏好画像 = 18 个类型偏好占比 + 4 个行为统计（活跃度、均分、评分波动、最近活跃），
  只用 ≤T1 的评分构建；行内归一化 + 连续维标准化。**一次构建、两算法共用**（同画像、同 k）。

## 6 指标

| 任务 | 指标 |
|---|---|
| 分类 | F1、ROC-AUC（主）、Precision、Recall、PR-AUC、阈值、混淆矩阵、正类比例、特征重要性（树模型为重要性，贝叶斯为各特征对数概率差） |
| 聚类 | k、轮廓系数、Davies-Bouldin、各群体规模/标签/偏离最大的 2～3 个类型/行为均值 |
| 降维 | n_components、解释方差比（NMF 为 null）、重构误差、资源开销（拟合秒数、峰值内存）、**对比实验**（全维与降维后同一聚类算法的 ARI/NMI 与轮廓系数） |

群体标签由数据驱动生成（例如"动作/科幻偏好 · 高活跃 · 评分偏严"），规则写进代码、可复现。

## 7 产物与目录

```
var/tasks/<编号>/status.json       任务状态（与清洗任务同构；供既有工具复用）
var/ml/<模型编号>/
  model.joblib 或 model.json        模型本体（含编码器/标准化器）
  meta.json                        元数据 sidecar（编号、类型、算法、生效超参、训练窗口、数据版本、特征清单、指标、泄漏说明、创建时间）
  profile.json                     群体画像（聚类的群体、标签、行为统计）
  labels.csv|jsonl                 每用户群标签（聚类）
  coords.csv|jsonl                 用户坐标（降维）
  index.json 的条目                 归档到 var/ml/index.json（携带数据版本 + 算法 + 参数指纹）
```

**对外**：`get_ml_model` 给元数据与指标；`list_ml_models` 给索引条目；产物清单里 `kind` 是文件格式、
`role` 是用途；模型文件经**新增的模型下载路由**流式取用（同一口令、白名单、不塞进调用参数）。

---

## 8 安全与护栏

- 模型编号与下载路径都做**形状校验**（单层编号、白名单内），不拼接用户字符串到命令或路径。
- 训练超参走白名单键；数值做上下界校验；`k` 与 `n_components` 有合理范围。
- 预测只读模型、不占执行位，但要有**单次时长上限**，避免异常输入把请求拖住。
- 内存约束：随机森林限树数与并行度，生效超参原样回显。

## 9 分段推进

| 段 | 内容 | 完成标志 |
|---|---|---|
| 0 地基 | 依赖装进独立环境；"训练任务并入现有体系"打通（用假训练验证受理→进度→取消→终态） | 既有工具能看见训练任务，不必新增入口 |
| 1 机器学习核心 | 数据加载与缓存、前缀聚合特征、分类两法、聚类两法+画像、降维两法+对比、指标 | 不接服务也能跑出真实指标 |
| 2 处理器 | 六个能力、模型登记与索引、产物清单、模型下载路由、只读资源 | 经服务可调用，字段与要求文档 §5 一致 |
| 3 验收 | 逐条对要求文档 §10 的八条；全量测试；文档更新 | 八条逐条有真实结论 |

## 10 风险与对策

| 风险 | 对策 |
|---|---|
| 内存吃紧（七Ｇ总量、集群占四Ｇ） | 限制树数与并行度；训练前打印内存估算；必要时提示先停集群（数据已缓存到本机） |
| 训练占住执行位（十几分钟） | 如实回"已有任务在运行"；训练可取消；超时上限兜底 |
| 防泄漏做错 | 前缀聚合按时间顺序消费样本，单测里造"未来数据"断言不影响历史样本特征 |
| 指标算错（小数位/口径） | 指标全部来自 sklearn 的真实计算；单测用可手算的小样本断言 |
| 依赖装不上或版本漂移 | 装进仓库内独立环境并把版本写进联调说明；缺依赖时如实报"环境不满足"而不是假装成功 |

## 11 计算安排：默认单机（非分布式）+ 预留作业聚合开关

**默认：单机、非分布式 —— 训练不提交任何集群作业。** 六种算法都在本机进程里算，只读已经落到本机的数据；
集群不参与训练，也不需要为训练而启动。

**默认路径（单机）**：训练在工作进程里用单机实现完成，取数从发布区缓存到本机。当前数据（一百万行、二十四兆）
下这是正确选择：调度开销远大于计算，六种算法都保留。

**预留开关（作业聚合）**：**纯端侧配置项**（默认关闭，**不作为工具参数对外**，对端无需感知也不需要传）。
打开后，训练前先跑**一节集群作业**，在集群上完成
"每个用户、每部电影在某个时点之前的历史统计 + 必要的抽样与聚合"，产出紧凑的画像表；
训练读这张表而不是上亿条原始评分。这样做的原因：随原始数据量增长的是**聚合**，不是模型本身；
把聚合交给集群之后，单机训练看到的仍是小表，层次聚类与矩阵分解这类没有分布式实现的算法也能保留。

**三堵墙的量化参考**（本机七Ｇ内存、集群占四Ｇ时）：

| 墙 | 当前规模 | 大致极限 | 表现 |
|---|---|---|---|
| 内存（稠密特征） | 一百万行 × 数十列 ≈ 两百多兆 | 几千万行量级 | 训练直接吃不下 |
| 时间（随机森林） | 一到几分钟 | 一亿行需数小时 | 并行在本机被拒、只能串行更慢 |
| 算法复杂度（凝聚层次） | 六千用户 | 一两万用户 | 两两距离矩阵爆内存 |

开关打开后，前两堵墙由集群承担；第三堵墙（层次聚类）仍是单机复杂度，靠"先聚合到用户级"把样本数压住。

**开关的对外形态（已定）**：只在端侧。改配置后重启服务生效；对外的工具参数**不增加任何一项**，
因此对端的能力表、前端界面、接口文档都不因它变化。打开时训练会多一个"聚合"阶段（进度如实反映），
并且该阶段需要集群在跑；关闭时与单机路径完全一致、不依赖集群。
