## 0 本轮已经定下的六件事

| 事项 | 结论 | 连带影响 |
|---|---|---|
| 对外协议 | 采用官方协议实现，服务以网络方式常驻虚拟机，宿主机上的 Agent 按标准方式连接 | 需要在仓库内装官方实现包；对端客户端要实现同样的标准连接 |
| 数据上传 | **不进入对 Agent 开放的能力清单**，Agent 对数据只有查看权 | 前端"资源"页的上传入口需要取消或改为提示；运维上传沿用现有脚本 |
| 任务完成如何告知 | 提供"等任务结束"的阻塞式等待，配合状态查询 | 不做服务端主动推送，少一层长连接与断线重连的复杂度 |
| 装包方式 | 在仓库内建独立运行环境，不碰系统自带解释器 | 该目录交付前清掉，已在清理清单覆盖 |
| 能力范围 | 端侧要求点名的全部工具，外加取证类、等待、取消、锁状态、健康检查 | 对外共二十项，全部出现在能力自描述里 |
| 验收强度 | 开发期不启集群；开发完成后集中启动一次，跑一遍全量，逐条对照九条验收 | 平时靠历史任务与小任务验证，真实作业只跑这一轮 |
| 端口与连法 | 用 8765；宿主机侧加一条端口转发；服务监听所有网络接口并带口令 | 转发规则由使用方在虚拟机软件里添加 |
| 中止任务 | 允许新增"已中止"状态，改动只落在状态写入这一处 | 取消后占用能自动释放，不会把任务永久挂在运行中 |
| 预计耗时 | 先填参考区间，收尾那次真实全量运行后统一成实测值 | 不额外增加运行次数 |
| 文档同步 | 由本方案作者同步端侧要求文档与对端接口文档 | 两份文档末尾各加一节"本轮确认的调整" |
| 工具命名 | 英文标识 + 中文说明 | 对端工具表可直接对接，用户看到中文 |

## 1 我要守的红线

1. **只做执行与取证。** 编排、意图理解、界面展示都不在本端；本端只回答"做了什么、结果是什么、为什么没做成"。
2. **判定在本端。** 缺数据、任务被占用、版本冲突，一律由本端自己判定并给出结构化结论。对端即使不拦，也不会让坏请求进来。
3. **不产生任何业务数字。** 所有数字只能来自真实作业产物；跑不出结果就如实报错，绝不填空值或示例值。
4. **只加不减。** 对外字段只增加不修改；确要改语义时，先升契约版本，再同时通知两端。
5. **不开放任意命令。** 能力清单是白名单；服务背后没有"执行任意程序"的入口。

## 2 部署与网络（本轮新增的现实约束）

**现状**：Agent 跑在 Windows 宿主机上，这台虚拟机是它的客户机，走默认的地址转换模式
（虚拟机地址 10.0.2.15，网关 10.0.2.2）。这种模式下虚拟机可以主动往外连，
**但宿主机不能反过来主动连进来**。也就是说：无论服务写得对不对，只要不在虚拟机软件里
加一条端口转发，宿主机那边就是连不上。这是本次最容易被忽略的一环。

| 项目 | 建议值 | 说明 |
|---|---|---|
| 监听地址 | 所有网络接口 | 必须。只监听本机回环时，端口转发过来接不上 |
| 端口 | 8765 | 当前机器上 3080（界面）与 22（远程登录）已被占用，8765 空闲 |
| 宿主机侧转发 | 宿主机本机 8765 → 虚拟机 8765 | 在虚拟机软件的网络设置里加一条；加完后宿主机按本机地址访问 |
| 访问口令 | 随机串，放 `var/mcp/` 下 | 该目录不入版本库；每次请求带在请求头里 |
| 健康检查 | 独立只读入口 | 只回答"活着吗、版本多少"，不触发任何作业 |

**备选连法**（如果加转发不方便）：

- 把网卡从地址转换改成桥接，虚拟机拿一个局域网地址，宿主机按地址直连。
  代价是虚拟机地址会变，机器上若干指向本机回环的配置要一起调整。
- 让虚拟机主动连宿主机（反向通道）。**不推荐**：需要宿主机上再跑一个接收端，
  两端都要多写一层，且与"Agent 主动调用数据处理"的方向相反。

**提醒**：这台机器上 Hadoop 的几个管理界面历史上只绑本机回环，8765 那条转发不影响它们；
将来若想在宿主机看这些界面，需要各自再加一条转发。

| 发起全流程 | 发起清洗+评分+发布 | 写 | 是 | 见 §3.4 | 范围、数据版本、标签、强制开关、两份方案 |
| 只清洗 | 发起只清洗的形态 | 写 | 是 | 见 §3.4 | 同上 |
| 独立评分 | 独立评分 | 写 | 是 | 见 §3.4 | 来源（原始/已发布/指定任务）、来源任务、评分方案 |
| 查状态 | 查状态 | 只读 | 否 | 毫秒 | 任务编号 |

### 3.2 取证与自描述（六项）

| 工具 | 回答的问题 | 数据来源 |
|---|---|---|
| 列已发布版本 | 发布区里有哪些数据版本、来自哪个任务、三表多大、什么时候发的 | 发布区目录（含随版本保存的内容清单文件） |
| 列任务产物文件 | 某个任务目录下有哪些文件、各多大、什么类型 | 任务目录，按扩展名粗分类型 |
| 读产物文件 | 某个产物的内容是什么（文本、结构化数据、Markdown） | 任务目录，有大小上限；其余类型只回"不可预览" |
| 取作业计数 | 隔离、去重、修复各多少条 | 任务产物里的计数文件与状态文件 |
| 取作业日志 | 作业当时报了什么 | 任务目录下的日志，回尾部若干行，有行数上限 |
| 能力自描述 | 你能做什么、参数是什么、哪个耗时长、契约版本多少 | 服务自身的工具表与版本常量 |

**能力自描述是对端工具表的权威来源**：本端工具集合有变化时，对端据此刷新，
不需要两端各自维护一份清单。

### 3.3 补充的四项

要求文档点名要"暴露锁与队列状态""支持取消"，但没有单列成工具；我把它们落成四条：

| 工具 | 用途 | 说明 |
|---|---|---|
| 等任务结束 | 挂起直到任务进入终态或等到超时 | 超时返回"仍在运行"而非失败，对端可重复等待 |
| 取消任务 | 请求中止一个在跑的任务 | 留了接口；当前实现需先确认能否真的停住（见 §7） |
| 查占用状态 | 现在有没有任务在跑、是谁、怎么解除 | 让对端能向用户解释"为什么现在发不出去" |
| 健康检查 | 探活与版本 | 独立只读，不触发作业 |

### 3.4 预计耗时怎么给

先按迭代一留下的实测记录填区间。**这里有一处材料不一致要如实说明**：接口文档里
全量全流程写的是"约八分钟"，而优化记录里写的是"二十到三十分钟"。我不替任何一方拍板，
实现时把这两个数字都作为参考，**收尾那次真实全量运行之后，用实测值统一两处说法**。
在拿到实测值之前，工具里给出的预计耗时只作参考，不承诺。

## 4 参数（不许收窄）

| 参数 | 取值 | 默认 | 必填 | 说明 |
|---|---|---|---|---|
| 范围 | 全量 / 小样本 | 全量 | 否 | 全量是正式用途；小样本仅联调，且**不会进入发布区**（现有实现已如此） |
| 任务类型 | 全流程 / 只清洗 | 全流程 | 否 | 只清洗只产出清洗结果，不评分不发布 |
| 执行方式 | 集群 | 集群 | 否 | **只接受集群执行**；本机本地执行属于排障手段，不对 Agent 开放 |
| 数据版本 | 字符串 | 取方案声明 | 否 | 与方案声明不一致时直接拒绝，并说明两边各是什么 |
| 清洗方案 | 方案文件路径 | 默认方案 | 否 | 自定义方案必须先校验 |
| 评分方案 | 方案文件路径 | 默认方案 | 否 | 同上 |
| 评分来源 | 原始 / 已发布 / 指定任务 | 无 | 是（评分时） | 指定任务时必须同时给来源任务编号 |
| 来源任务编号 | 任务编号 | 无 | 条件必填 | 评分来源为"指定任务"时必填 |
| 强制开关 | 是 / 否 | 否 | 否 | 忽略"已有任务在跑"的冲突；返回里会提示风险 |
| 标签 | 字符串 | 空 | 否 | 便于人认任务 |
| 样本类型 | 清洗后 / 隔离区 | 隔离区 | 否 | — |
| 表名 | 评分 / 用户 / 电影 | 评分 | 否 | — |
| 条数 | 非负整数 | 五 | 否 | 有上限，防止一次拉太多 |
| 报告格式 | 全文 / 结构化 | 全文 | 否 | — |
| 任务编号 | 任务编号字符串 | 无 | 是（查类工具） | 不存在时明确回"任务不存在" |

**硬约束三条**（与要求文档 §5 一致）：

1. 自定义方案支持"先校验再执行"；校验不通过的方案**绝不允许**进入执行。
2. 数据版本、清洗规则版本、评分方案版本、时间边界**四者成组**出现，不跨版本混用。
3. 时间边界（训练期截止、验证期截止）由第一轮统一确定，随结果一起返回，不由对端自行推断。

## 5 返回形状

所有工具都回一种带版本的信封，成功与失败共用外壳。字段集合：

| 组 | 字段 | 说明 |
|---|---|---|
| 外壳 | 是否成功、契约版本 | 一眼判断成败；版本用于能力协商 |
| 任务 | 任务编号、状态 | 状态取值：排队 / 运行 / 成功 / 失败（是否新增"已中止"见 §7） |
| 进度 | 阶段名、阶段序号、阶段总数、进度百分比 | 运行中必须真实反映，不能长期停在零 |
| 时间 | 开始时间、更新时间 | 统一时间格式，便于对端比对 |
| 计数 | 输入、输出、隔离、去重、修复 | 只来自真实作业产物 |
| 评分 | 清洗前、清洗后、变化量 | 只来自真实评分产物 |
| 版本 | 数据版本、规则版本、评分版本、策略版本、算子库 | 血缘，缺一不可 |
| 时间边界 | 训练期截止、验证期截止 | 同上 |
| 产物 | 编号、标题、类别、类型、相对路径、大小 | 对端"结果/文件"板块可直接渲染 |
| 错误 | 错误码、说明、细节、来源码 | 见第 6 节的保留规则 |

补充三条：长任务在受理时就给出预计耗时；产物位置一律是"任务编号 + 相对路径"，
不暴露机器上的绝对位置；**信封里不出现任何未经作业产出的数字**。

## 6 错误语义（不得丢）

| 现有退出码 | 结构化错误码 | 什么场景会出现 | 建议的补救动作 |
|---|---|---|---|
| 0 | 无错误 | 正常完成 | — |
| 2 | 参数不合法 | 取值越界、必填缺失、枚举不对 | 核对参数取值与必填项 |
| 2 | 方案校验失败（**保留原码**） | 清洗或评分方案本身有问题 | 按细节列表逐条修方案 |
| 2 | 前置依赖缺失 | 原始数据不可读、目标任务的清洗产物不存在、发布区不存在 | 按说明补齐后再试 |
| 2 | 已有任务占用 | 上一个任务还没结束 | 等占用者结束，或使用强制开关 |
| 3 | 任务失败 | 作业链中某一步失败 | 看失败阶段与作业日志定位 |
| 4 | 任务不存在 | 编号不存在或已清理 | 核对编号 |
| 5 | 任务未完成 | 任务还没到终态就要结果 | 等完成后再取 |
| 6 | 版本冲突 | 同版本不同内容（方案或输入变了而版本没升） | 升数据版本，或回退方案变更 |
| — | 无输出 / 非法输出 / 不可达 / 超时 | 本端内部执行通道出问题 | 重试；持续出现则查本端服务状态 |

**保留规则**（与对端契约一致，两处不能各说一套）：

- 已经是明确错误类别的，**原样向上传递**，绝不压成笼统错误；
- 只有退出码可依时，才按上表换算，并把原退出码单独留档，便于排障；
- 补救动作要写在说明里，让对端能直接转述给用户。

**新增的只读类错误**：文件不存在、路径越界、内容过大、不可预览。这四条对端接口文档
§3.11 里已有相近命名的错误码，我会**沿用对端的名字**，避免两端各造一套。
（原本还要有"不支持的文件类型"和"上传过大"，本轮上传不开放，这两条随之取消。）

## 7 长任务与唤醒

- **受理即返回。** 发起类工具立刻回任务编号与"已受理"，不在调用里阻塞等待作业跑完。
- **进度来自真实状态文件。** 阶段名与百分比直接读任务状态文件，不是按时间估算；
  只清洗与独立评分各有自己的阶段序列，不会假装跑全流程。
- **阻塞式等待。** 对端调一次等待工具，挂到任务进入终态或到达等待上限为止；
  等待上限可配，超时回"仍在运行"而不是失败，对端可重复等待，断线也只需重来一次。
- **取消。** 现有后台作业是以独立进程组启动的，可以按任务定位到进程组发送
  终止信号。**已确认**：允许新增"已中止"状态（改动只落在状态写入这一处），
  中止后占用随之释放，不会把任务永久挂在运行中。
- **服务重启不丢任务。** 任务状态的唯一真相在任务目录里的状态文件，服务自身不持有
  唯一副本；服务重启后仍能查、仍能等、仍能取结果。
- **中断的发出者是对端。** 本端只负责如实回答"到终态了没有、结果是什么"，不主动
  往对话里注入内容。

## 8 依赖与互斥（本端自己判定）

| 操作 | 前置条件 | 互斥与并行 |
|---|---|---|
| 发起全流程 / 只清洗 / 对原始数据评分 | 原始三表可读 | 占用任务锁，与其他写操作串行 |
| 对指定任务评分 | 目标任务是成功状态，且清洗产物存在 | 占用任务锁 |
| 对已发布数据评分 | 发布区存在对应版本 | 占用任务锁 |
| 发布 | 收尾产物存在 | 发布互斥，且受内容比对保护 |
| 查询类（状态、结果、样本、报告、任务列表、方案、文件、资源） | 无 | 只读，可并行 |

- 条件不满足 → 明确回"缺少什么"（哪个任务、哪份产物、哪个目录），而不是笼统失败。
- 已被占用 → 明确回"占用者是谁、怎么解除"。强制开关用与不用，返回里都要写清后果。
- 锁与队列状态可单独查询，供对端向用户解释"现在为什么发不出去"。

## 9 版本与发布保护

- **发布区只增不改**：已发布的数据不许原地变动，只能以新数据版本演进。
- **发布前比对内容**：与发布目录里随版本保存的内容清单比对。内容相同 → 幂等放行；
  同版本但内容不同 → 拒绝，并说明"方案或输入已变，必须升数据版本"。
- **血缘随产物走**：每个产物都带上它使用的数据版本、规则版本、评分版本与时间边界。
- **目录布局是对下游的承诺**：清洗三表、隔离区、报告、指标的相对位置不变；
  确需变布局，只能通过新数据版本实现，不偷偷改路径。

## 10 只读资源

用协议自带的"资源"能力暴露只读产物，让对端按需取用，不必为每种产物单开一个工具：

| 资源 | 内容 |
|---|---|
| 已发布数据版本 | 版本列表与各自的来源任务、三表文件、大小、发布时间 |
| 清洗产物清单 | 某任务清洗后的三表文件与大小 |
| 隔离样例 | 某任务隔离区样本，带命中规则与原因 |
| 评估报告 | 全文与结构化两种 |
| 方案文件 | 清洗规则与评分方案的完整内容（供"评分依据"展示） |

资源只读，读取时同样做根目录白名单与大小上限；越界一律拒绝并说明。

## 11 安全约束

1. **白名单能力清单**，服务背后没有任意命令执行入口。
2. **文件访问限定三个根**：任务产物目录、方案目录、原始区与发布区。解析真实路径后校验
   必须落在根内，拒绝上级跳转、绝对路径与符号链接逃逸。
3. **上传不开放给 Agent**，运维上传沿用现有脚本（它已经承担打包、物化行号、上传三件事）。
4. **访问口令**：每次请求带令牌；口令文件不入版本库。
5. **读写分离标注**：每条能力标明只读还是写入；写能力受占用与版本保护约束。
6. **日志不含敏感信息**，作业日志只按需回尾部片段。

## 17 实现期发现的差异与已知限制

以下都是写代码时**实际撞上**的、文档与实现对不上的地方。逐条给出本轮的处置，
需要改既有实现或改文档的，单独标出来等确认。

| # | 发现 | 本轮处置 | 是否要动既有代码 |
|---|---|---|---|
| 1 | **独立评分没有强制开关**。driver 的评分子命令规格里根本没有这个选项，传进去会被静默忽略；占用检查处也是无条件拒绝 | 参数保留在工具表（对端可发现），但**不传给 driver**，并在返回里明确写"该开关在这条路上不生效"，绝不假装生效 | 否（若要真支持，driver 需加选项，属另一轮） |
| 2 | **评分的前置条件文档少写一条**：对指定任务评分，除"任务成功且清洗产物存在"外，还要求该任务维表产物齐全 | 依赖缺失时如实透传 driver 的说明，本端不另立一套判断 | 否（建议补文档） |
| 3 | **版本冲突里"方案声明的那一版"只在文字说明中**，没有独立字段，本端无法结构化地并排展示两边版本 | 原样转述 driver 的话，另把用户请求的版本单列一个字段 | 否（建议 driver 补字段） |
| 4 | **driver 成功信封带任务目录绝对路径**，与"不暴露机器绝对位置"的红线冲突 | 处理器里丢弃该字段，对外只给任务编号 | 否（建议 driver 侧就不放进对外信封） |
| 5 | **占用说明带命令行口吻**（原文提到"加某个开关"），对 Agent 与用户不友好 | 保留原话不覆盖，另补一段工具层面的说明 | 否（建议改文案） |
| 6 | **强制开关的豁免范围比名字宽**：它同时绕过"任务编号已存在"的判断 | 本端不指定任务编号，因此碰不到；已在文档记下，将来若允许指定编号要拆开 | 否 |
| 7 | **校验方案的告警清单永远为空**（driver 未实现告警计算） | 如实返回空，不编造提醒 | 否 |
| 8 | **判定顺序**：数据版本冲突的检查排在占用检查之前，因此在跑任务时给错版本，得到的是版本冲突而非占用冲突 | 原样保留该顺序，不调整 | 否 |
| 9 | **"只清洗 + 非集群执行"的拒绝路径实际打不到**：本端固定按集群传参 | 透传而不自行判定，测试里锁定"原话逐字不改" | 否 |
| 10 | **集群链路不写任务元数据文件**（现有任务目录里一个都没有，只有本机引擎那条路写），因此"查状态顺带给版本与时间边界"在集群任务上取不到 | 允许从**成功任务的结果文件**兜底，并在返回里标出处（元数据 / 结果），两处都没有就不给该字段 —— 不推算 | 否（建议执行侧也给集群任务写元数据） |
| 11 | **取结果会把机器上的绝对位置一并交出去** | 对外改成"任务编号 + 相对路径"；分布式文件系统上的路径（发布区）保留原样，它不是某台机器的本地位置 | 否 |
| 12 | **发布区不保存来源任务**，所以"列已发布版本"里的来源任务字段取不到 | 取不到就不出现，不拿任务列表去猜 | 否（要补得在发布环节多写一份元数据） |
| 13 | **状态命令不回任务类型与数据范围**（状态文件里其实存着） | 从状态文件补这两个字段与标签，让对端能区分全流程 / 只清洗 / 独立评分以及是否小样本 | 否 |
| 14 | **产物内容损坏与产物不存在需要区分** | 契约新增 `PRODUCT_INVALID`（文件在但内容读不出或不合法），与"文件不存在"分开，补救办法不同 | 否（契约加性新增） |
| 15 | **前台方式发起的任务无法按进程定位**（执行体就在发起它的终端里，不在后台子进程里） | 取消时如实拒绝并说明要在那个终端里中断；写进能力说明，避免用户以为取消失灵 | 否 |
| 16 | **"状态写着在跑、进程其实已消失"会让执行位永久挂住**，而取消不敢凭"没找到进程"改状态（怕误伤别人在前台起的任务） | 受理成功时由本服务在任务目录写一个"本次任务由服务提交"的标记；取消时**有标记且进程确实不在**才落成已中止并释放执行位，无标记则保守拒绝并说明只能人工处理 | 否（只写本服务自己的标记文件） |
| 17 | **状态文件是原地覆盖写**，没有临时文件加替换，极端情况下并发读可能读到半个文件 | 读侧如实报"状态文件无法解析"，不猜内容；原子写属执行侧改动，超出本轮 | 否 |
| 18 | **中止任务的进度停在原处**（有意为之，如实反映停在哪一步） | 若对端有"终态一律满进度"的预设，需要提前告知 | 否 |
| 19 | **服务自己的控制文件会混进产物清单**（中止标记、提交标记） | 列产物与读产物时一律排除；文件名集中成常量便于将来扩展 | 否 |
| 20 | **集群模式下"自定义清洗方案"并未真正生效**：作业实际用的是随引擎包分发的仓库默认配置，`--rules` 指定自定义方案只影响驱动端的本地环节（校验、报告、发布判定） | 端侧要求 §4 把"自定义方案"列为参数，本轮**如实记录而不改**：这是执行侧的行为，改动需先确认是否在本次范围内 | **是**（下一轮候选） |
| 21 | 给对端的客户端示例曾有一处**参数被静默丢弃**：为下载动作新增第二个位置参数后，调用动作的第一对"键=值"被它吃掉，表现为"调用成功但服务端说缺参数" | 已修：位置参数统一收在一个剩余参数里，按动作再分派；并补了十六条命令行解析的回归测试锁住这条路径 | 否 |

### 21.2 会让对端误解返回的（已处置）
