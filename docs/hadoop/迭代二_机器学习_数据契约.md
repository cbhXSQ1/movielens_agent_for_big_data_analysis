# 迭代二 · 机器学习数据契约（输入 / 输出结构与会类型）

> 用途：把两侧的数据结构与类型写死，避免"一端给 A、一端以为要 B"。
> 依据：`docs/hadoop/迭代二_机器学习端侧开发要求.md`（§5 返回字段、§12 实现说明）与本端实现方案。
> 阅读方式：**左列是字段名，右列是类型与约束**；"必给"表示本端一定返回，"条件"表示视情况出现，
> "不收"表示本端明确不接受或明确不提供。

---

## 0 总则

| 项 | 约定 |
|---|---|
| 信封 | 成功：`ok=true` + `interface_version`（当前 `1.0`）+ 业务字段；失败：`ok=false` + `interface_version` + `error{code,message,...}` |
| 进程/对象标识 | 模型编号与任务编号**同一个值**，形如 `ml-20261018-103000-a1b2`（前缀 `ml-`、单层、可安全拼进路径） |
| 时间 | 一律 ISO8601 世界协调时，形如 `2026-10-18T10:30:00Z`；只给秒级，不给本地时区 |
| 比率类指标 | **0～1 之间的小数，保留四位**（例如 AUC 0.7846）；百分比换算由前端负责 |
| 计数类 | 非负整数 |
| 分数/金额类 | 不涉及 |
| 路径 | 一律**相对路径**（相对任务目录或模型目录）；本机绝对路径不对外 |
| 空值 | 用 `null` 显式表达"该项不适用"（例如 NMF 的解释方差比），**不用空字符串代替** |
| 数组 | 无内容时给空数组 `[]`，不给 `null`（除非语义是"不适用"） |

## 1 输入的参数契约（六个能力）

### 1.1 三个训练能力共有参数

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| `data_version` | string | 否 | 发布区当前版本（`ml1m-clean-v1`） | 必须是发布区里存在的版本；不存在 → `DEPENDENCY_MISSING` |
| `tag` | string | 否 | 无 | 最长 64 字符；仅备注，不参与计算 |
| `params` | object | 否 | `{}` | 算法超参键值对；**未知键一律拒绝**（`USAGE` 并列出可用键）；数值有上下界 |

### 1.2 各能力自己的参数

| 能力 | 参数 | 类型 | 必填 | 默认 | 取值 / 约束 |
|---|---|---|---|---|---|
| `train_classifier` | `algorithm` | string | 是 | — | `naive_bayes` / `random_forest` |
| `cluster_users` | `algorithm` | string | 是 | — | `kmeans` / `hierarchical` |
| `cluster_users` | `k` | int | 否 | 端侧按轮廓系数与肘部法选定 | 2～50；**两种聚类算法共用同一个 k** |
| `reduce_dimensions` | `algorithm` | string | 是 | — | `pca` / `nmf` |
| `reduce_dimensions` | `n_components` | int | 否 | 端侧选定 | 2～20（不超过画像维度） |
| `predict_high_rating` | `model_id` | string | 是 | — | 必须是已登记的**分类**模型；不存在 → `MODEL_NOT_FOUND`；类型不符 → `USAGE` |
| `predict_high_rating` | `user_id` | string 或 int | 是 | — | 用户编号；不存在于发布数据 → `USAGE`（说明该编号不在数据里） |
| `predict_high_rating` | `movie_id` | string 或 int | 是 | — | 同上 |
| `list_ml_models` | — | — | — | — | 无参数 |
| `get_ml_model` | `model_id` | string | 是 | — | 不存在 → `MODEL_NOT_FOUND` |

### 1.3 `params` 对象的可用键（白名单）

| 能力 | 键 | 类型 | 默认 | 范围 | 说明 |
|---|---|---|---|---|---|
| 分类（两算法共用） | `n_estimators` | int | 120 | 10～500 | 随机森林树数；朴素贝叶斯忽略此项 |
| 分类（两算法共用） | `max_depth` | int 或 null | null | 2～40 | 随机森林最大深度；null 表示不限制 |
| 分类（两算法共用） | `min_samples_leaf` | int | 1 | 1～200 | 随机森林叶最小样本数 |
| 分类（两算法共用） | `threshold` | number | 0.5 | 0.05～0.95 | 判定为正类的概率阈值（**只影响报告的分类结果与混淆矩阵**） |
| 分类（朴素贝叶斯） | `alpha` | number | 1.0 | 0.001～10 | 拉普拉斯平滑 |
| 聚类（两算法共用） | `random_state` | int | 42 | 0～2³¹−1 | 可复现用种子 |
| 聚类（两算法共用） | `max_iter` | int | 300 | 50～2000 | 迭代上限 |
| 降维（两算法共用） | `random_state` | int | 42 | 0～2³¹−1 | 可复现用种子 |
| 降维（NMF） | `init` | string | `nndsvda` | `nndsvda` / `random` | 初始化方式 |
| 降维（NMF） | `max_iter` | int | 400 | 50～2000 | 迭代上限 |

> `params` 里出现的、但上表没有的键 → `USAGE`，说明里列出该算法可用的键。
> 最终**生效值**（含端侧自选的 `k` / `n_components` 与因内存限制被下调的并行度）会在返回的 `params` 字段里原样回显。

## 2 输入的数据契约（发布区）

| 表 | 文件 | 字段（顺序固定） | 类型 | 说明 |
|---|---|---|---|---|
| 评分 | `ratings.dat` | `UserID`、`MovieID`、`Rating`、`Timestamp` | int、int、number、Unix 秒 | `::` 分隔；评分 1～5 |
| 用户 | `users.dat` | `UserID`、`Gender`、`Age`、`Occupation`、`Zip-code` | int、string、int、int、string | `::` 分隔 |
| 电影 | `movies.dat` | `MovieID`、`Title`、`Genres` | int、string、string（`|` 分隔的类型串） | `::` 分隔 |

- 编码：数据文件为 ISO-8859-1（拉丁一），输出 JSON 为 UTF-8。
- 时间边界：`T1=2001-12-31T23:59:59Z`、`T2=2002-06-30T23:59:59Z`，取自方案声明，随结果返回。
- 数据版本与内容清单：发布目录里带内容清单，本端按它判断缓存能否复用。

## 3 输出的数据契约

### 3.1 训练类能力（三个）的成功返回

| 字段 | 类型 | 必给 | 说明 |
|---|---|---|---|
| `model_id` | string | 是 | 与任务编号同值 |
| `status` | string | 是 | 五态：`queued` / `running` / `succeeded` / `failed` / `aborted` |
| `status_label` / `status_cn` | string | 是 | 中文状态名（两个键同值，兼容两种命名） |
| `task_type` | string | 是 | `classification` / `clustering` / `dimensionality_reduction` |
| `algorithm` | string | 是 | 六种算法之一 |
| `data_version` | string | 是 | 使用的数据版本 |
| `time_boundaries` | object | 是 | `{"T1": ISO8601, "T2": ISO8601}` |
| `params` | object | 是 | **生效**超参（含端侧自选项与被下调项） |
| `metrics` | object | 任务成功时必给 | 见 3.2 / 3.3 / 3.4；受理阶段不出现 |
| `artifacts` | array | 任务成功时必给 | 见 3.5 |
| `created_at` | string | 是 | 受理时间 |
| `started_at` / `finished_at` | string | 条件 | 有则给 |
| `estimated_seconds` | int | 受理时给 | 预计耗时（**估算值，会显式标注**） |

### 3.2 分类 `metrics`

| 字段 | 类型 | 说明 |
|---|---|---|
| `f1` | number | 主指标之一 |
| `auc` | number | ROC-AUC，主指标 |
| `precision` / `recall` | number | — |
| `pr_auc` | number | 正类不平衡时的补充指标 |
| `threshold` | number | 实际使用的判定阈值 |
| `confusion_matrix` | object | `{tp, fp, tn, fn}`，均为 int |
| `positive_rate` | number | 数据中正类比例 |
| `feature_importance` | array | `[{feature: string, importance: number}]`；朴素贝叶斯给"各特征对后验的对数概率差"并在 `feature_importance_note` 里说明含义；不可用时给 `[]` |
| `split_sizes` | object | `{train: int, valid: int, test: int}`，便于核对数据划分 |
| `leakage` | object | `{"policy": string, "verified_on": string}` —— 说明防泄漏做法与核验方式 |

### 3.3 聚类 `metrics`

| 字段 | 类型 | 说明 |
|---|---|---|
| `k` | int | 实际使用的簇数 |
| `silhouette` | number | 轮廓系数 |
| `davies_bouldin` | number | — |
| `clusters` | array | 每项见下 |
| `k_selection` | object | 条件：仅在未传 `k` 时出现，`{"method": string, "candidates": [{"k": int, "silhouette": number}]}` |

`clusters[]` 每项：

| 字段 | 类型 | 说明 |
|---|---|---|
| `cluster_id` | int | 0 起 |
| `size` | int | 群体规模 |
| `label` | string | 自动生成的中文群体标签 |
| `top_genres` | array[string] | 2～3 个偏离最大的类型 |
| `behavior` | object | `{activity: number, avg_rating: number, rating_std: number, recency: number}` |

### 3.4 降维 `metrics`

| 字段 | 类型 | 说明 |
|---|---|---|
| `n_components` | int | 实际维度 |
| `explained_variance_ratio` | array[number] 或 null | PCA 专有；NMF 为 `null` |
| `reconstruction_error` | number | 重构误差 |
| `resource` | object | `{fit_seconds: number, mem_mb: number}` |
| `comparison` | object | 见下 |

`comparison`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `before` / `after` | object | `{silhouette: number, davies_bouldin: number, k: int}`（降维前 / 后各做一次同一聚类算法） |
| `agreement` | object | `{ari: number, nmi: number}`，两套分组的一致性 |

### 3.5 产物条目 `artifacts[]`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | `模型编号:相对路径` |
| `title` | string | 中文标题（如"模型本体""群体画像""每用户群标签""用户坐标""模型元数据"） |
| `kind` | string | **文件格式**：`joblib` / `json` / `csv` / `jsonl` / `md` / `other` |
| `role` | string | **用途**：`model` / `profile` / `labels` / `coords` / `meta` |
| `path` | string | 相对模型目录的路径 |
| `size` | int | 字节数 |

> 与要求文档的差异：要求文档把"类型"写成用途（模型/画像/…）。本端**`kind` 一律表示文件格式**、
> 新增 **`role` 表示用途**，同一字段在全服务含义一致；前端按 `role` 分类、按 `kind` 判断能否在线预览。

### 3.6 预测返回

| 字段 | 类型 | 说明 |
|---|---|---|
| `model_id` | string | 回显 |
| `user_id` / `movie_id` | string | 回显（统一成字符串，前端按需转换） |
| `prediction` | object | `{label: 0 或 1, probability: number, threshold: number}` |
| `model_version` | string | 模型指纹（参数 + 数据版本摘要） |

### 3.7 列模型 / 取模型

`list_ml_models` 返回 `models` 数组，每项：`model_id`（string）、`task_type`（string）、`algorithm`（string）、
`data_version`（string）、`created_at`（string）、`metrics_summary`（object，键随任务类型：分类给 `f1`/`auc`，
聚类给 `k`/`silhouette`，降维给 `n_components`/`reconstruction_error`）。

`get_ml_model` 返回 `model`，字段与 3.1 对齐（`metrics`、`artifacts`、`params`、`time_boundaries` 全给）。

### 3.8 模型元数据（落盘的 sidecar，与对外字段同名）

| 字段 | 类型 |
|---|---|
| `model_id`、`task_type`、`algorithm`、`data_version`、`created_at` | string |
| `params`、`metrics`、`time_boundaries` | object |
| `feature_spec` | object：`{features: array[string], encoders: array[string], leakage: object}` |
| `artifacts` | array（同 3.5） |
| `version_fingerprint` | string：数据版本 + 算法 + 参数指纹的摘要 |

## 4 交付形式（文件与格式）

| 内容 | 格式 | 位置 |
|---|---|---|
| 模型本体（含编码器/标准化器） | `joblib` | 模型目录下 |
| 元数据 sidecar | `json` | 模型目录下 |
| 群体画像 | `json` | 模型目录下 |
| 每用户群标签 | `csv` 或 `jsonl` | 模型目录下 |
| 用户坐标（降维） | `csv` 或 `jsonl` | 模型目录下 |
| 索引 | `json` | 模型根目录下（列模型读它） |

**取用方式**：模型目录里的文件通过**模型下载路由**流式取用。形状与现有两段下载完全同构：

### 4.1 模型下载路由（确切形状）

| 项 | 取值 |
|---|---|
| 方法与路径 | `GET /download/model/{model_id}/{path}` |
| `{model_id}` | 模型编号，形如 `ml-20261018-103000-a1b2`；**单层**，只允许字母数字与 `.-_` |
| `{path}` | **模型目录内的相对路径**，可含多级（如 `profile.json`、`labels.csv`、`sub/coords.csv`），按 URL 编码传入 |
| 鉴权 | 请求头 `Authorization: Bearer <口令>`；**不接受把口令放在地址里** |
| Host 校验 | 与现有下载路由同一份允许列表（`127.0.0.1:任意端口` 等） |
| 响应（成功） | `200`，流式返回文件正文；带 `Content-Length`、`Content-Disposition: attachment; filename="<文件名>"`；`Content-Type` 按扩展名给：`json`→`application/json`、`csv`→`text/csv`、`jsonl`→`application/x-ndjson`、`md`→`text/markdown`、`joblib` 及其它→`application/octet-stream` |
| 响应（失败） | JSON 错误信封（结构见 §5），**不返回半截文件** |

**失败与状态码**：

| 状态码 | 错误码 | 触发条件 |
|---|---|---|
| 400 | `FORBIDDEN_PATH` | 路径越界（上级跳转、绝对路径、符号链接逃逸）、或落在不允许外发的类别（隐藏文件、校验和附属物、流程残留）；细节里带 `reason_kind`（`sidecar` / `residue` / `not_regular_file`） |
| 400 | `USAGE` | `model_id` 形状不合法 |
| 401 | `UNAUTHORIZED` | 未带或错误的访问口令 |
| 403 | `FORBIDDEN_HOST` | 请求的 Host 不在允许列表 |
| 404 | `FILE_NOT_FOUND` | 模型编号不存在、或该相对路径下没有文件（若是目录，同样按"没有文件"回，并在 `reason_kind` 里给 `directory`） |

**可下载清单从哪来**：不是靠猜路径，而是调 `get_ml_model` 拿 `artifacts`，用其中的 `path`（相对模型目录）
拼出地址即可。也就是说"能下载什么"与"元数据里列了什么"是同一份来源，不会出现列得出下不来的情况。

**不做的三件事**：不支持把口令写进地址；不支持范围请求（续传）；不提供"整包打包下载"（需要时按 `artifacts` 逐个取）。

### 4.2 对端使用建议（下载按钮怎么摆）

产物清单里每个条目同时带两个字段：**`kind` 是文件格式**（`joblib` / `json` / `csv` / `jsonl` / `md`），
**`role` 是用途**（`model` 模型本体 / `profile` 群体画像 / `labels` 每用户群标签 / `coords` 用户坐标 / `meta` 模型元数据）。

建议对端这样用：

- **按 `role` 分组展示**：下载按钮按"模型本体 / 群体画像 / 每用户标签 / 用户坐标 / 模型元数据"分组，
  用户一眼知道每个文件是干什么用的；不要按 `kind` 分组（那会把同一用途的文件拆散）。
- **按 `kind` 决定交互**：`json` / `csv` / `jsonl` / `md` 这类文本可以直接下载给用户看；
  `joblib` 是二进制模型，界面上应提示"需用对应工具加载"，不要提供在线打开。

**一处限制要说清**：本轮模型产物**只提供下载，不提供在线预览**（预览能力只覆盖任务目录里的文本类产物）。
元数据 `meta.json` 若想在线查看，建议前端下载后本地渲染，或直接把 `get_ml_model` 返回的字段渲染出来
（两者同一份来源，不必再取文件）。

## 5 错误码与触发条件

| 错误码 | 触发条件 | 附带信息 |
|---|---|---|
| `MODEL_NOT_FOUND` | 预测或取模型时编号不存在 | `model_id` |
| `DEPENDENCY_MISSING` | 发布区缺少指定版本或三表数据 | 缺什么（版本/表名） |
| `TASK_ALREADY_RUNNING` | 执行位被占用（清洗任务或另一个训练任务） | 占用者编号与解除办法 |
| `USAGE` | 参数非法：算法取值不对、`params` 未知键、编号不在数据里、模型类型不符、数值越界 | `param` 与可用取值 |
| `TASK_FAILED` | 训练过程失败（含超时） | 阶段、原始说明、结构化码 |
| `WAIT_LIMIT_REACHED` | 同时等待的人数达到上限 | 上限值与当前占用数 |
| `ABORTED` | 对已中止的任务取结果/报告/样本 | 中止时间 |
| `UNAUTHORIZED` / `FORBIDDEN_HOST` | 口令不对 / 访问地址不在允许列表 | — |

## 6 本端明确不提供的东西

| 项 | 说明 |
|---|---|
| 模型二进制内联返回 | 模型只经下载路由取，不塞进调用参数（数据表与模型都有几十兆量级） |
| 批量预测 | 本轮只有单条（用户 × 电影）预测；批量留给需要时再加 |
| 分布式训练 | **默认路径不提交任何集群作业**：训练在本机单进程完成，Hadoop 只作为**数据来源**（清洗产物在分布式文件系统里）。分布式聚合是端侧可选开关，默认不启用 |
| 模型删除 | 本轮不做；模型与产物保留供后续轮次复用 |
| 模型热加载服务 | 预测按需加载模型，不常驻内存 |
| 训练期使用验证/测试数据 | 防时间泄漏是硬约束：历史特征只由预测时点之前的数据聚合 |

## 7 与要求文档的差异、以及需要两边点头的地方

| # | 事项 | 本端做法 | 对端需要做什么 | 状态 |
|---|---|---|---|---|
| 1 | **能力粒度** | 每类一个训练能力、算法用参数选，共六项（`train_classifier` / `cluster_users` / `reduce_dimensions` / `predict_high_rating` / `list_ml_models` / `get_ml_model`） | 远端能力表按六个名字改；要求文档 §3 的九项口径同步 | 待确认 |
| 2 | **产物字段** | `kind` 一律表示文件格式；新增 `role` 表示用途 | 前端按 `role` 分类、按 `kind` 判断能否预览 | 待确认 |
| 3 | **指标单位** | 零到一之间的小数、保留四位 | 前端显示百分比时自行乘一百 | 已定 |
| 4 | **训练占用执行位** | 训练期间执行位被占，发起清洗会被拒并给出占用者 | 界面原样展示"已有任务在运行、占用者是谁" | 待确认 |
