# 迭代二 · Hadoop 侧能力交付后，Agent 与前端需要改什么

> 面向：Agent 侧开发、前端开发。
> 前提：Hadoop 侧的能力服务已完成并通过全量验收（详见 `docs/hadoop/迭代二_MCP_实现方案.md`）。
> 本文只讲**对端要做什么**，不重复 Hadoop 侧的内部实现。
> 一句话概括：**能力已经可以被调用，但两端之间有六处接口语义变了，不改会出错。**

---

## 0 先看这张表：六处必须改的地方

| # | 事情 | 现状 | 不改会怎样 |
|---|---|---|---|
| 1 | 远端客户端还是空实现 | Agent 侧目前没有任何东西真的连过来 | 所有远端能力都调不通，只能继续走本机模拟 |
| 2 | 原始数据上传不再由 Agent 经手 | Hadoop 侧**不提供**上传能力 | 前端上传按钮会失败；用户以为传上去了 |
| 3 | 任务状态多了"已中止" | 前端任务视图与状态映射只认四种 | 中止后的任务显示成"运行中"或空白 |
| 4 | 错误码集合扩充 | 对端映射表里没有新增的码 | 出现无法归类的错误，只能显示原始码，用户看不懂 |
| 5 | 长任务没有服务端推送 | 对端没有"等任务结束"的调用方式 | 只能自己轮询；若不做轮询，任务完成也不会被唤醒 |
| 6 | 二进制产物下载换了通道 | 对端仍按本地文件系统想象下载 | 下载按钮拿不到数据，或把整份数据读进内存 |

下面逐条给出**具体怎么改**。

## 1 Agent 侧：把远端客户端真正接上

### 1.1 连接方式

Hadoop 侧是一个常驻服务，用**标准协议**对外，传输方式是 HTTP（入口路径 `/mcp`）。
对端不必自己实现协议，直接用官方客户端即可：

- 连上后先握手，再做"列工具 / 调工具 / 读资源"。
- 每次请求都要带口令：请求头 `Authorization: Bearer <口令>`。**口令不要写进日志**。
- 健康检查单独一条路（`/health`），**不需要口令**，只回答"活着吗、版本多少"，
  并在返回里给出一段"可用入口"（协议入口、健康检查、两段下载路由各自的地址形状）——
  两段下载路由不在能力自描述里，对端可以从这里发现它们。

### 1.2 地址与端口

- 虚拟机侧固定监听 `8765`；**宿主机侧用哪个端口由你定**（本轮联调用的是宿主机 `8900` 转到虚拟机 `8765`）。
- 虚拟机走的是默认地址转换模式，**宿主机不能主动连进来**，必须在虚拟机软件里加一条端口转发，否则连不上。
- 服务放行本机回环的任意端口（`127.0.0.1:任意端口`、`localhost:任意端口`、`[::1]`），所以端口号换了不用改服务配置。

### 1.3 对端接口形状（照这个实现即可）

Agent 侧已有的占位接口是：列工具、调工具、查任务状态、订阅完成、版本协商、接口版本属性。
对应到本服务：

| 对端接口 | 本服务怎么满足 |
|---|---|
| 列工具 | 标准"列工具"调用；也可用 `describe_capabilities` 拿到更全的清单（含中文说明、只读/写入、是否长耗时、预计耗时） |
| 调工具 | 标准"调工具"调用，参数名见工具清单；**返回内容永远是我们的信封**（见 §4） |
| 查任务状态 | `get_task_status`（也可直接读只读资源，见 §6） |
| 订阅完成 | **本服务不提供主动推送**。用 `wait_for_task` 阻塞等待，或用 `get_task_status` 定期查询。中断仍由 Agent 侧发出 |
| 版本协商 | 信封里带 `interface_version`（当前 `1.0`），能力自描述里同时给出执行侧契约版本 |

**关于"订阅完成"的替代方案**：`wait_for_task` 会挂到任务进入终态或到达你给的等待上限；
超时返回的是"仍然在运行"（`timed_out=true`），**不是失败**，可以再等一次。建议等待上限设置成
你愿意挂起的时长（例如十分钟一轮），这样可以边等边让用户看到进度。

## 2 工具清单（二十三项）与调用要点

### 2.1 与既有能力一一对应的十项

| 工具 | 干什么 | 关键参数 | 备注 |
|---|---|---|---|
| `validate_config` | 校验清洗/评分方案 | `rules`、`scoring` | 自定义方案必须先过这一步 |
| `list_schemes` | 列已登记方案 | — | — |
| `start_cleaning_task` | 发起全流程（清洗+评分+发布） | `scope`、`data_version`、`tag`、`force`、`rules`、`scoring` | **长任务**，约十七分钟（全量实测） |
| `start_clean_task` | 只清洗（不评分不发布） | 同上 | **长任务** |
| `score_task` | 独立评分 | `source`（原始/已发布/指定任务）、`from_task`、`scoring` | **长任务**；`source=task` 时必须给 `from_task`；**没有强制开关**（执行侧不支持，传了会被明确拒绝） |
| `get_task_status` | 查状态与进度 | `task_id` | 进度是真实阶段，不是估算 |
| `get_task_result` | 取权威结果 | `task_id` | 含评分对比、计数、版本、时间边界、产物清单 |
| `get_samples` | 取清洗后/隔离区样本 | `task_id`、`sample_type`、`table`、`limit` | 不传参数时默认取「清洗后」的「电影表」（与命令行一致）；条数本端上限 2000 |
| `get_report` | 取报告 | `task_id`、`format`（全文/结构化） | 不传格式时默认给结构化数据（与命令行一致）；要 Markdown 全文请显式指定 |
| `list_tasks` | 列最近任务 | — | — |

### 2.2 取证与自描述六项

`list_published_versions`（已发布版本）、`list_raw_datasets`（原始区已有的数据集与文件）、
`list_task_files`（任务产物清单）、`read_task_file`（读产物内容，文本类）、
`get_scheme_content`（取方案完整内容，供评分依据展示）、
`get_job_counters`（隔离/去重/修复计数）、`get_job_logs`（日志尾部）、
`describe_capabilities`（能力自描述，**工具表的权威来源**）。

### 2.3 自定义方案上传（新增，2026-10-18）

| 工具 | 干什么 | 参数 |
|---|---|---|
| `upload_scheme` | 上传自定义的清洗规则或评分方案 | `name`（必填，单层 `.json` 文件名）、`content`（必填，方案内容）、`type`（可选：清洗规则 / 评分方案，缺省由内容判定）、`overwrite`（默认否） |

行为要点：

- **先校验后落盘**：内容先过与"校验方案"同等的校验；**不通过就一个文件都不写**，返回里带回校验明细。校验窗口用的是隐藏临时文件（不带 `.json` 后缀），所以中途不会在"列方案"里露出半成品。
- 通过后写进与已登记方案同一个目录，返回条目与"列方案"的字段对齐（方案标识、类型、版本、登记状态、**路径形如 `config/<文件名>`**），可以直接拿这个路径去"校验方案"或发起任务。
- **同名已存在默认拒绝**（结论是专用码 `SCHEME_EXISTS`，不是版本冲突码），要覆盖得显式传"允许覆盖"；允许覆盖时同样是先校验通过才替换，**校验不过不会破坏原文件**。
- **两份随仓库交付的默认方案不允许被上传覆盖**（即使要求覆盖也拒绝，结论是参数错误），请另起文件名。
- 内容超过 1 MB → `CONTENT_TOO_LARGE`；内容不是合法 JSON、顶层不是对象、缺必需字段、类型判不出 → `CONFIG_INVALID` 并带明细。
- 内容里必须带方案标识（否则写进目录也列不出来，会当场说明而不是静默接受）。

**对端要做的**：在自己的远端能力表里补上这一条（形状以上面的参数为准），前端保留上传入口、改为经 Agent 带口令转发到本服务；上传成功后刷新远端方案列表即可。**在此之前**，前端上传仍是"本机暂存"，界面上要标注清楚，避免用户以为传到了远端。

### 2.4 补充四项

| 工具 | 干什么 | 备注 |
|---|---|---|
| `wait_for_task` | 等任务到终态 | 超时**不是失败**，返回 `timed_out=true` 可重复等待。单次上限三十分钟（建议一轮几分钟）；服务端限制同时等待的数量，达到上限会**立刻**回 `WAIT_LIMIT_REACHED` 而不是排队 |
| `cancel_task` | 取消任务 | 已结束的任务返回"无需中止"；无法确认的会保守拒绝并说明原因 |
| `get_scheduler_state` | 查执行位占用 | 有占用时给出占用者与解除办法 |
| `health_check` | 探活 | 不触发任何任务 |

### 2.5 参数名的六处不一致（联调阶段最容易集中爆发）

对端现有的本地工具与本服务的远端能力**同名但参数名不同**，一旦沿用旧名字调用，会集中收到
"不认识的参数"这类参数错误。请按下表改对端的工具规格（本服务的名字以能力自描述与列工具为准）：

| 能力 | 对端本地写法 | 本服务用 | 怎么处理 |
|---|---|---|---|
| `get_samples` | `n` | `limit` | 改名；另注意上限不同：对端 200，本服务 2000 |
| `get_samples` | `sample_type` 注释写"默认隔离区" | 默认是**清洗后**（与命令行一致） | 建议显式传值，不要依赖默认 |
| `get_report` | `fmt` | `format` | 改名；另注意默认不同：对端默认全文，本服务默认结构化 |
| `start_cleaning_task` / `start_clean_task` | `foreground` | **不提供** | 本服务一律异步受理；要等结果用"等任务结束" |
| `start_cleaning_task` / `start_clean_task` | `exec_mode`（cluster / local） | **不提供** | 固定集群执行；本机本地执行属于排障手段，不对 Agent 开放 |
| `score_task` | `foreground` | **不提供** | 同上；另外本服务的独立评分**没有强制开关** |

两端都有的参数（`task_id`、`rules`、`scoring`、`data_version`、`tag`、`scope`、`force`、
`source`、`from_task`、`table`）名字一致，可以直接沿用。

对端还有一个只在本机跑的能力（快速演示清洗），本服务不提供对应能力，**继续留在本机**即可。

### 2.6 三条调用纪律

1. **长任务发起后立刻返回任务编号**，不要在调用里等它跑完（否则会占住连接十几分钟）。
2. **进度只能来自查状态**，不要用时间估算进度，也不要自己编"大约还剩几分钟"。
3. **失败就如实转述**：信封里的说明已经写成可以直接讲给用户听的话，不要改写成别的结论。

## 3 双编号怎么对

Agent 侧内部有自己的任务编号（`agent_task_id`），Hadoop 侧返回的是 `task_id`（`hadoop_task_id`）。
要求：

- 保存两者的映射，**所有后续调用（查状态、等待、取结果、取样例、取报告、取消、产物清单、下载）都用 `hadoop_task_id`**；
- 用户界面展示用 `agent_task_id`（或你生成的任务名），但排障信息里要能查到 `hadoop_task_id`；
- 不要拿 Agent 自己的编号去调本服务，也不会被猜到或推断出来。

## 4 返回信封：对端要认哪些字段

调工具拿到的永远是这一种信封（成功与失败共用外壳）：

| 字段 | 含义 | 对端怎么用 |
|---|---|---|
| `ok` | 成败 | 一眼判断 |
| `interface_version` | 契约版本（当前 `1.0`） | 判断能力可用性 |
| `task_id` / `status` / `status_label` / `status_cn` | 任务编号、状态取值、中文状态名 | 两个中文字段取值相同（`status_label` 是本端命名，`status_cn` 是对端已有命名），用哪个都行 |
| `stage` / `stage_index` / `stage_total` / `progress_percent` | 阶段与进度 | 进度条直接用 `progress_percent` |
| `started_at` / `updated_at` / `finished_at` | 时间 | 统一是世界协调时；未结束时不出现 `finished_at` |
| `counts` | 输入/输出/隔离/去重/修复 | 数据量变化板块 |
| `scores` | 清洗前/后/变化量 | 五维对比板块 |
| `versions` / `version_hashes` / `data_version` | 四类版本与摘要 | 版本展示、血缘 |
| `time_boundaries` | 训练期与验证期截止 | 直接展示 |
| `versions_source` | 版本信息取自哪里（元数据/结果） | 可选的诚实标注，建议展示为小字说明 |
| `artifacts` | 产物清单（编号、标题、类别、类型、相对路径、大小） | **结果板块的文件区直接用** |
| `limitations` | 局限说明 | 结果板块的"依据与局限" |
| `error` | 失败时的 `{code, message, details…}` | 见 §5 |
| `error.reason_kind` | 细类标记（失败时可能带） | 取值 `control`（服务控制文件）、`sidecar`（隐藏文件或校验和附属物）、`residue`（流程中途残留）、`directory`（是个目录）、`not_regular_file`（命名管道等，不是普通文件）；按码统一处理、按它细分提示即可 |

**产物类别的用法**：`artifacts[].category` 取值有 数据 / 隔离 / 报告 / 指标 / 元数据 / 日志 / 其它。
全量任务实测产物共 47 项，其中日志占 29 项 —— 结果板块若只想展示"算出了什么"，
建议按类别过滤成 数据 / 隔离 / 报告 / 指标 / 元数据，日志放到单独的文件区。

**路径规则**：产物路径一律是**相对任务目录的相对路径**（例如 `cleaned/ml1m-clean-v1/ratings.dat`），
本机绝对路径不会出现。发布区这类**集群路径**保留原样（它不是某台机器上的位置）。

## 5 错误码：对端要扩充映射表

原有映射保留，新增下面这些（都能在失败信封的 `error.code` 里出现）：

| 新错误码 | 什么场景 | 建议给用户的话 |
|---|---|---|
| `ABORTED` | 对一个已中止的任务取结果 | 任务已中止，不会再变化、没有结果可取（**不要当成「未完成」反复重试**） |
| `FILE_NOT_FOUND` | 文件不存在 | 该产物不存在，可能已被清理 |
| `FORBIDDEN_PATH` | 路径越界 | 该路径不允许访问 |
| `CONTENT_TOO_LARGE` | 文件过大 | 文件太大，预览只支持较小的文本产物 |
| `NOT_PREVIEWABLE` | 不可预览 | 该文件不支持在线预览，请下载 |
| `PRODUCT_INVALID` | 产物存在但内容损坏/不可用 | 该产物内容异常，可以先看其它产物或日志 |
| `CANCEL_FAILED` | 取消未生效 | 没能停住这个任务，原因见说明 |
| `UNAUTHORIZED` | 口令缺失或错误 | 连接凭据不对，请检查配置 |
| `FORBIDDEN_HOST` | 请求的 Host 不在允许列表 | 访问地址不被允许（通常是端口转发配错） |
| `SCHEME_EXISTS` | 上传的方案文件名已存在且未允许覆盖 | 换个名字，或确认后显式允许覆盖 |
| `WAIT_LIMIT_REACHED` | 同时等待的数量已达上限 | 现在等的人太多；改用较短的等待或稍后再试（本次没有等待、也没做任何改动） |
| `INTERNAL_ERROR` | 本服务内部异常 | 带异常类型与说明，便于排障 |

**保留规则不变**：执行侧自产的码（方案校验失败、任务占用、依赖缺失）原样保留，不被降级；
仅当只有退出码可依时才按表换算，并把原退出码记进 `driver_code` 留档 —— 排障时请把 `driver_code` 一并显示。

## 6 前端：资源面板与结果板块怎么改

### 6.1 必须改的三处

| 位置 | 改成什么 |
|---|---|
| 原始数据上传按钮 | **移除**或改成提示"请到运行数据的机器上上传"。Hadoop 侧不提供上传能力，Agent 不再转发文件 |
| 任务状态映射 | 增加"已中止"（服务直接给 `status_label`，用它最省事） |
| 长任务的"完成"判定 | 不再依赖服务端推送；用"等任务结束"或定期查状态 |

### 6.2 资源页四段分别取什么

| 面板 | 用什么 |
|---|---|
| 原始数据 | `list_published_versions` 之外的原始数据没有对外能力（上传已关闭）。原始区要从机器上运维脚本维护 |
| 已发布数据 | `list_published_versions`（版本名、三表文件与大小、发布时间） |
| 方案文件 | `list_schemes` 列方案 + `read_task_file` 不适用；方案内容用只读资源 `ml://scheme/<文件名>` 或 `get_report` 之外的方案读取能力（资源读取最直接） |
| 任务产出文件 | `list_task_files`（相对路径/大小/类型）+ `read_task_file`（文本类预览）+ 下载路由（见 §8） |

### 6.3 结果板块

直接消费 `get_task_result` 的返回即可，六个数据块对应关系：

| 板块 | 字段 |
|---|---|
| 五维评分对比 | `scores.before` / `scores.after` / `scores.delta` |
| 数据量变化 | `counts.input` / `counts.output` / `counts.quarantine` / `counts.dedupe` / `counts.fix` |
| 隔离样例 | `get_samples`（`sample_type=quarantine`），带命中规则与原因 |
| 评估报告 | `get_report`（全文或结构化） |
| 任务状态 | `task_id` / `status_label` / `versions` / `time_boundaries` |
| 依据与局限 | `limitations` |

任务还没到终态时取结果会**明确拒绝**（`TASK_NOT_FINISHED`），不要用旧数据或样例顶替。

## 7 状态取值：五态对照

| 服务返回值 | 中文 | 对端要不要区分 |
|---|---|---|
| `queued` | 排队 | 是 |
| `running` | 运行 | 是 |
| `succeeded` | 成功 | 是 |
| `failed` | 失败 | 是 |
| `aborted` | 已中止 | **新增**，必须能显示，且不能再当成"运行中" |

中止后的任务：进度会停在停下的那一步（这是有意的，如实反映），不要强行显示成百分之百。

## 8 下载：走服务的只读下载路由

**不要**试图用"读产物内容"那个工具下载数据文件 —— 它只支持文本类预览，且有大小上限。

两段下载路由（普通 HTTP GET，**带同一个口令**）：

| 用途 | 地址形状 |
|---|---|
| 任务产物 | `/download/task/<任务编号>/<相对路径>` |
| 已发布数据 | `/download/published/<数据版本>/<表名>` |

要点：

- 成功时**流式**返回文件内容，带下载文件名与长度；数据表三十多兆也能直接下载，不会把内存吃满。
- 鉴权与协议入口同一个口令；**不支持把口令写在地址里**。所以：**由 Agent 侧带请求头取回，再转给浏览器**，不要把这个地址直接塞给前端用。
- 不可下载的东西会被拒：路径越界、服务内部的控制文件、隐藏文件、校验和附属物、流程中途的临时残留。
- 失败会明确区分："集群连不上"与"这个版本没发布过"是两句话，不要合并成一句。

## 9 前端要新增的三件小事

1. **产物类别徽标**：用 `artifacts[].category` 区分数据/报告/日志等，日志类默认折叠。
2. **版本与时间边界**：结果里的四类版本与两个时间边界直接展示，不要自己推断。
3. **等任务结束的进度提示**：长任务期间展示阶段名与百分比；`wait_for_task` 超时不是错误，提示"仍在运行，可继续等待"。

## 11 契约版本与兼容

- 本服务对外契约版本当前为 **`1.0`**（与 Agent 侧占位里写的版本一致，两端同号）。
- 只做**加性变更**：新增字段、新增工具、新增错误码都不升版本；字段语义变化才会升版本，并会提前通知。
- 执行侧的自有契约版本是 `1.1`，只作为信息出现在能力自描述里，不参与两端的版本判断。

## 12 还有一处**已知限制**，请对端知情

- **前台方式发起的任务无法被取消**：如果任务是在机器终端里以前台方式起的，服务定位不到它的执行进程，
  取消会如实拒绝并说明要在那个终端里中断。经本服务发起的任务都带凭据，可以正常取消。
- **评分"指定任务"之外的两类来源**（已发布、原始数据）依赖检查发生在受理之后：
  请求会先被受理，再由后台判定依赖是否满足。这不是遗漏，而是因为这两类判断要问集群，
  集群没起来时无法把"连不上"与"确实没有"分开，宁可晚一步也不误报。
