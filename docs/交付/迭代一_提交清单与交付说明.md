## 三、系统说明（按课程"相关文档"要求合并生成）

### 3.1 定位与总体架构

一句话：**用户在前端说人话，Agent 组织任务，Hadoop 真实执行清洗与五维评分；全程版本化、可追溯、不编造。**

```
[前端 静态页（零构建，零依赖）] --HTTP--> [Agent 层（零依赖 HTTP 服务 / 11 端点 / 9 工具 / 可选 LLM 增强）]
        --CLI + JSON 信封--> [driver（8 子命令 / 9 阶段编排 / 发布与版本保护）]
        --HDFS/YARN 客户端--> [Hadoop 3.3.6 伪分布式：15 趟 Streaming 作业（清洗 + 统计 + 评分）]
```

### 3.2 从一句话到一个报告（运行逻辑）

1. 前端 `POST /api/chat`：**意图解析**（规则词表为主、9 类意图；可选 LLM 增强只做"理解 + 润色"，默认关闭）→ 前端显示 `intent_cn`（"我理解成什么"）；
2. `POST /api/tasks` → driver `start`（异步）：任务进入 **9 阶段**状态机：`clean_users → clean_movies → clean_ratings → stats_marks → score_before → score_after → finalize → publish → done`；
3. **清洗**：维表先行（users/movies）再评分类表；各类表按"校验/修复 → 去重/冲突解决 → 跨表引用"多趟作业处理；坚持**修复 / 去重 / 隔离三分**，隔离记录保留原始行 + 规则 + 原因 + 行号；
4. **评分**：`before = 原始数据` / `after = 清洗结果`，**同一评分方案、同一 sha256**；基础计数由 MapReduce 产出，`score_finalize` 生成五维分与综合分；
5. **发布**（集群模式）：cleaned 三表复制到 `/data/published/<data_version>/`；**已存在则比对内容哈希（清单随发布目录保存），不一致直接报 `VERSION_CONFLICT`——必须升版本，不许静默覆盖**（D-017）；
6. **展示与追问**：前端五视图 + 追问（进度 / 结果 / 样本 / 报告 / 任务列表 / 方案列表）；所有数字来自任务真实产出；任务未完成或失败时**拒绝返回结果**，只给状态与失败原因。

### 3.3 版本与时间边界（统一口径）

| 项 | 值 | 说明 |
|---|---|---|
| data_version | `ml1m-clean-v1` | 清洗产物版本；发布不可覆盖 |
| rule_version | `1.0.0` + sha256 | `config/cleaning_rules.v1.json` |
| scoring_scheme_version | `1.0.0` + sha256 | `config/scoring_scheme.v1.json` |
| policy_version | sha256 | 处置策略取值集合哈希 |
| **T1** | **2001-12-31 23:59:59 UTC** | 训练期截止：`Timestamp ≤ T1` 用于训练（迭代二、三沿用） |
| **T2** | **2002-06-30 23:59:59 UTC** | 验证期截止：`(T1, T2]` 为验证集；T2 之后为测试集 |
| 可比性 | 仅同一 (rule, scoring) 版本内分数可比 | 换方案必须升版本并在报告中标注 |

### 3.4 关键工程保证（可当场验证）

- **黄金测试 = 集群结果**：全量 1,150,241 行输入，本地 runner 与 Hadoop 集群产出三表 **sha256 逐字节一致**（重构前 40 趟、D-014 精简后 15 趟，各对账一次）；
- **测试**：`hadoop/scripts/run_tests.sh` 全部通过（含黄金基线 17 项断言）；`hadoop/tools/validate_configs.py` PASS；
- **不编造**：失败拒绝返回结果；"隔离 ≠ 修复"同屏展示；所有数字来自 Hadoop counters 与结果文件；
- **一键复现**：`docs/hadoop/runbook.md` + `docs/agent/虚拟机联调_傻瓜步骤.md`（含 30 秒故障速查）。

## 五、实验配置（合并生成）

- **清洗方案**：`config/cleaning_rules.v1.json`——27 条规则（解析/校验/修复/去重/冲突/跨表/报告）；修复 48 + 13,503 + 47 + 73；去重 49,510 / 726 / 454；隔离 100,830；
- **评分方案**：`config/scoring_scheme.v1.json`——五维固定；18 指标逐条含公式（ratio/freshness）、权重、适用局限、无法验证项；综合分启用；
- **执行模式**：`--exec cluster`（正式口径，约 8–10 分钟）/ `--exec local`（本地演示，不发布 HDFS）；`--scope full`（默认）/ `sample`（联调）；
- **LLM 可选层**：默认关闭（`AGENT_LLM_SUPPORTED`）；前端"大模型设置"面板（只存 localStorage）或环境变量 `AGENT_LLM_*`；已实测 DeepSeek；护栏 = 数字占位符 + 四道输出校验，失败自动回落规则；
- **环境坐标**：VMware Ubuntu 22.04（用户 `hadoop`）/ Hadoop 3.3.6 / OpenJDK 11 / 数据 `~/data/raw/ml-1m` / 集群 6 守护进程（含 JobHistoryServer）。

## 七、已知限制（合并生成，如实）

1. **意图解析**：规则词表为主（9 类意图 + 白名单参数），LLM 为**单步可选增强**（理解 + 润色、默认关闭）；**不支持多步工具编排**——标准 function-calling 循环列入下一轮；
2. **自定义方案**：清洗规则/评分方案的**接口层已支持**（`validate`、`start --rules/--scoring`、`POST /api/tasks` 带 `rules/scoring`），前端编辑入口未做；
3. **数据源**：单一已登记原始版本（课程允许事先配置），未做多数据源切换界面；
4. **不可验证项**：用户属性为自愿填写未核验（A3/C1 不封顶是诚实口径）；时效性以其发布语境衡量；
5. **分数解释**：Unique/Consistent 的提升部分来自"隔离出分母"（报告已披露）；隔离只统计 quarantine 类规则，去重单列；
6. **规模**：伪分布式单机；架构可横向扩展，但未做多机部署验证；
7. **演示环境依赖**：VM 需管理员启动、集群 6 进程、后端 8 行环境变量——已提供一键流程与 30 秒故障速查。
