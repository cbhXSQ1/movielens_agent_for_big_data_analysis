## 四、Q&A 准备（合并版）

| 问题 | 答案要点 |
|---|---|
| **这是不是标准 LLM agent？** | **不是**。本轮是"确定性工具编排 + LLM 可选增强（单步理解 + 润色）"；标准 function-calling 多步循环列入下一轮——工具 schema、护栏、执行层已就绪，升级不返工。（诚实口径，比硬撑安全） |
| 为什么用规则匹配，不直接全用 LLM？ | 离线可跑、结果确定、答辩可解释；LLM 默认关闭、只做理解与润色；失败自动回落规则。 |
| 能自定义清洗规则/评分方案吗？ | 能——接口层：`validate` 校验 + `start --rules/--scoring` 或 `POST /api/tasks{rules, scoring}`；前端编辑入口下一轮；自定义方案产物与默认方案**不可比**（版本不同）。 |
| 数据源能换吗？ | 文档允许事先配置；本轮为单一已登记版本；迭代二消费本轮发布的 cleaned 版本。 |
| 为什么 Python + Streaming？ | Streaming 是 Hadoop 官方组件；开发/测试效率高、与 Agent 同栈；机制不受影响（HDFS/YARN/shuffle/counters 全真实参与）。 |
| 一台机器也算集群吗？ | 伪分布式 = 全部角色同机，机制与真实集群一致；架构可横向扩展（未做多机验证，如实）。 |
| 40 趟还是 15 趟作业？ | D-014 重构：41 → 15 趟（标签流 + 单 reducer 汇总）；重构前后**均逐字节对账通过**。 |
| 发布会不会被覆盖？ | D-017：哈希清单随发布目录保存、**跨任务生效**；同版本内容不一致 → `VERSION_CONFLICT`，必须升版本。 |
| `quick_clean` 是什么？ | 附加演示工具（同引擎同数、不经 Hadoop、不发布）；**权威结果永远以 `start + result` 为准**。 |
| 遇到最大的坑？ | 例：JobHistoryServer 缺失导致成功被误报失败（D-013）；`hadoop-env.sh` 绝对路径（R3）；发布保护失效（D-017）——均在 `docs/issues.md` / `decisions.md` 留档。 |
| 结果可复现吗？ | 三级版本写入任务元数据 + 发布不可覆盖 + 哈希对账 + 一键复现脚本（runbook）。 |
| 数据质量分数凭什么可比？ | 清洗前后使用**同一份评分方案**（同版本、同 sha256）；换版本即不可比并需标注。 |
