# 前端（第 6 节）· MovieLens 1M 数据治理控制台

迭代一「Agent 驱动的 Hadoop 数据清洗与五维质量评估」的前端页面。

**零构建、零依赖、零 CDN。** 纯原生 HTML + CSS + JavaScript，图表全部为手写内联 SVG。
目标环境可能完全离线，因此不引用任何外部字体、图标库或图表库。

---

## 1. 目录

```
frontend/
├── index.html          页面结构（顶栏 + 左栏「对 Agent 说 / 执行情况 / 追问」+ 右栏五个视图）
├── css/app.css         设计契约的全部 token 与组件样式
├── js/api.js           与 Agent HTTP 接口之间的唯一通道（含错误码 → 中文）
├── js/charts.js        手写内联 SVG：雷达图 / 分组条形 / 输入输出对比
├── js/scoring.js       「评分依据」页：直接读 config/*.json 渲染
└── js/app.js           状态机、轮询、全部渲染
```

## 2. 怎么跑

前端是静态页面，但它需要**同时**访问两个东西：

| 目标 | 地址 | 说明 |
|---|---|---|
| Agent HTTP 接口 | `http://localhost:8765` | 由 `agent/http_api.py` 提供 |
| 配置文件 | `/config/*.json` | 「评分依据」页要读，**必须与页面同源** |

所以启动顺序是两步。

### 第 1 步：起后端（另开一个终端）

```bash
cd <仓库根目录>
python -m agent.http_api --port 8765
```

看到 `Agent HTTP API 已启动` 即成功。没起的话页面顶栏会显示「后端未连接」并给出提示。

### 第 2 步：起静态服务（**必须在仓库根目录**）

```bash
cd <仓库根目录>
python -m http.server 8080
```

然后浏览器打开：

```
http://localhost:8080/frontend/
```

> **为什么必须在仓库根目录起？**
> 「评分依据」页要 `fetch('../config/scoring_scheme.v1.json')`。
> 从仓库根目录起服务时，页面地址是 `/frontend/`、配置在 `/config/`，属于**同源**，能直接读取。
> 如果直接从 `frontend/` 目录起服务，配置就取不到了 —— 前端会如实显示错误并告诉你原因，
> 而不是把规则硬编码进 JS。

## 3. 换接口地址

只改一处：`js/api.js` 顶部的

```js
var API_BASE = 'http://localhost:8765';
```

页面已按同源策略设计，跨机部署时把这里改成后端所在主机即可（后端已开 CORS）。

## 4. 怎么用（一次提示的完整闭环）

1. 在左栏输入框说一句中文（或点示例 chip），选执行方式，点「发送给 Agent」。
2. Agent 把这句话解析成一次工具调用，页面显示它识别出的意图（如「发起清洗 + 五维评估任务」）。
3. 若意图是发起任务，页面自动开始轮询进度（每 3 秒），显示 9 个阶段的步进器与百分比。
4. 任务成功后自动读取结果，右侧五个视图填充**真实数字**。
5. 继续追问：直接在「追问 Agent」里说人话，例如「跑到哪一步了」「给我看 5 条被隔离的评分记录」。
6. 「样例与报告」页可以按类型/表/条数取真实样例，并加载完整评估报告（Markdown，可复制、可下载）。

**执行方式的两种口径**（重要）：

| 选项 | 含义 | 能否用于汇报 |
|---|---|---|
| **Hadoop 集群**（默认） | 走 HDFS + YARN，约 8–10 分钟 | ✅ 正式口径 |
| 本地引擎 | 同一套引擎但不经 Hadoop，快 | ❌ 仅快速预演，页面会显示告警横幅 |

## 5. 三条不会被违反的规矩

1. **不编造**：任务未成功时，结果区**一个数字都不显示**，只显示状态与失败原因。
   接口返回 `TASK_NOT_FINISHED` 时页面继续显示进度，绝不拿上一轮旧数字顶替。
2. **隔离 ≠ 修复**：「清洗结果」页顶部常驻提示条，说明被隔离的记录是**移出正表**而不是被修好；
   五维分数与数据量变化始终同屏。
3. **配置只读**：规则、阈值、指标、权重全部来自 `config/*.json` 与接口返回；
   前端不硬编码任何领域规则。指标名也是从评分方案里查出来的。

## 6. 抽样警戒

页面会自动核对输入行数：`counts.input.ratings_lines` 等于全量基准 **1,150,241** 时显示绿色「全量运行」，
否则挂**黄色持久横幅**提示「抽样运行，数字不可用于汇报」。这条是为了防止把样本数字当成正式结果。

## 7. 已知限制（如实说明）

| # | 限制 | 说明 |
|---|---|---|
| 1 | **没有取消按钮** | driver 与 Agent 都没有提供取消任务的接口。因此页面不画一个点了没用的按钮，改为明确显示进度、已用时，并在超过 1 分钟后提示全量任务通常需要 8–10 分钟。 |
| 2 | **「本地引擎」不是正式口径** | 它用同一套引擎在本地跑完清洗与评分，自第 4 节的 **D-015** 起**不再依赖 HDFS**（`publish()` 在非集群模式下是 no-op，`paths.published_dir` 为 `null`），因此在没有 Hadoop 的机器上也能成功。但课程要求「清洗与评分必须由 Hadoop 实际执行」，正式数字必须来自「Hadoop 集群」模式 —— 页面依据**结果自带**的 `published_dir` 判断执行环境，用**黄色横幅**（本地引擎）或**绿色横幅**（Hadoop 集群）明确区分。 |
| 3 | **`rule_notes` 是文档外的字段** | 结果里带「口径差异说明」，但接口文档 §4.5 的示例没有它。前端做成「有就显示、没有就说明本次没有」，不假设它一定存在。 |
| 4 | **字体回落** | 设计契约指定 IBM Plex，本机通常未安装；离线环境不允许 CDN 字体，因此按契约声明的回退链落到 `Segoe UI / Microsoft YaHei`。中文由系统字体渲染。 |
| 5 | **中文行高与契约的拉丁值不同** | 契约的行高是拉丁口径（正文 1.5 / 标题 1.17）。中文必须用 1.7 / 1.35，否则多行中文会上下相碰。这是 craft 规则里明确要求的 CJK 覆盖，已在 `app.css` 顶部注明。 |

## 8. 设计契约

界面遵循 Open Design 设计系统 **`ibm`（IBM Carbon 风格）**，关键约束逐条落实在 `css/app.css`：

- 0 圆角（按钮 / 输入框 / 卡片）；24px 胶囊只用于 tag
- 卡片无边框、无阴影，层次靠背景色分层
- 唯一强调色 Blue 60 `#0f62fe`，同屏可见使用不超过 2 处
- 输入框只有 2px 底边框，不做四周描边
- 8px 栅格；字重仅 300 / 400 / 600
- 禁用渐变、装饰性阴影、emoji 图标

图表颜色单独一套（清洗前 = 中性灰，清洗后 = 语义绿），不占用强调色配额。
