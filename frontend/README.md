# 前端（第 6 节）· MovieLens 1M 数据治理控制台

迭代一「Agent 驱动的 Hadoop 数据清洗与五维质量评估」的前端页面。

**零构建、零依赖、零 CDN。** 纯原生 HTML + CSS + JavaScript，图表全部为手写内联 SVG。
目标环境可能完全离线，因此不引用任何外部字体、图标库或图表库。

---

## 1. 目录

```
frontend/
├── index.html          页面结构（顶栏 + 左栏「对 Agent 说 / 执行情况 / 追问」+ 右栏五个视图）
├── css/app.css         设计契约的全部 token 与组件样式
├── js/api.js           与 Agent HTTP 接口之间的唯一通道（含错误码 → 中文）
├── js/charts.js        手写内联 SVG：雷达图 / 分组条形 / 输入输出对比
├── js/scoring.js       「评分依据」页：直接读 config/*.json 渲染
├── js/llm-settings.js  大模型 API 接入弹窗（入口常显；后端未开启时如实说明并置灰）
└── js/app.js           状态机、轮询、全部渲染
```

## 2. 怎么跑

前端是静态页面，但它需要**同时**访问两个东西：

| 目标 | 地址 | 说明 |
|---|---|---|
| Agent HTTP 接口 | `http://localhost:8765` | 由 `agent/http_api.py` 提供 |
| 配置文件 | `/config/*.json` | 「评分依据」页要读，**必须与页面同源** |

所以启动顺序是两步。

### 第 1 步：起后端（另开一个终端）

```bash
cd <仓库根目录>
python -m agent.http_api --port 8765
```

看到 `Agent HTTP API 已启动` 即成功。没起的话页面顶栏会显示「后端未连接」并给出提示。

### 第 2 步：起静态服务（**必须在仓库根目录**）

```bash
cd <仓库根目录>
python -m http.server 8080
```

然后浏览器打开：

```
http://localhost:8080/frontend/
```

> **为什么必须在仓库根目录起？**
> 「评分依据」页要 `fetch('../config/scoring_scheme.v1.json')`。
> 从仓库根目录起服务时，页面地址是 `/frontend/`、配置在 `/config/`，属于**同源**，能直接读取。
> 如果直接从 `frontend/` 目录起服务，配置就取不到了 —— 前端会如实显示错误并告诉你原因，
> 而不是把规则硬编码进 JS。

## 3. 换接口地址

只改一处：`js/api.js` 顶部的

```js
var API_BASE = 'http://localhost:8765';
```

页面已按同源策略设计，跨机部署时把这里改成后端所在主机即可（后端已开 CORS）。

## 4. 怎么用（一次提示的完整闭环）

1. 在左栏输入框说一句中文（或点示例 chip），选执行方式，点「发送给 Agent」。
2. Agent 把这句话解析成一次工具调用，页面显示它识别出的意图（如「发起清洗 + 五维评估任务」）。
3. 若意图是发起任务，页面自动开始轮询进度（每 3 秒），显示 9 个阶段的步进器与百分比。
4. 任务成功后自动读取结果，右侧五个视图填充**真实数字**。
5. 继续追问：直接在「追问 Agent」里说人话，例如「跑到哪一步了」「给我看 5 条被隔离的评分记录」。
6. 「样例与报告」页可以按类型/表/条数取真实样例，并加载完整评估报告（Markdown，可复制、可下载）。

**执行方式的两种口径**（重要）：

| 选项 | 含义 | 能否用于汇报 |
|---|---|---|
| **Hadoop 集群**（默认） | 走 HDFS + YARN，约 8–10 分钟 | ✅ 正式口径 |
| 本地引擎 | 同一套引擎但不经 Hadoop，快 | ❌ 仅快速预演，页面会显示告警横幅 |

### 左栏的三段结构

左栏是**定高列，自己不再整体滚动**，分三段：

| 段 | 内容 | 行为 |
|---|---|---|
| 上区（`.rail__scroll`） | 对 Agent 说 + 执行情况 | **自己滚动** —— 内容最长、也最少被回看 |
| 主操作栏（`.rail__action`） | 「发送给 Agent」+ 一条折叠说明 | **常驻**，不跟着说明文字滚走 |
| 追问区（`.rail__block--chat`） | 追问 Agent | 高度可拖，**永远可见、不用滚** |

发起任务后，上区会**自动滚到「执行情况」**，演示时不用手动拖。

### 两条分隔条

左栏/右栏之间、主操作栏/追问区之间各有一条可拖的分隔条：

| 操作 | 竖向（左右栏宽度 280–720px） | 横向（追问区高度 180–562px） |
|---|---|---|
| 拖动 | 调宽，松手后记住 | 向上拖 = 追问区变高 |
| 双击 / `Enter` / 空格 | 恢复默认 | 恢复默认 |
| `←` `→` / `↑` `↓` | 每次 16px，Shift 48px | 每次 24px，Shift 64px |
| `Home` / `End` | 最窄 / 最宽 | 追问区最高 / 最矮 |

两条都**键盘可达**（`role="separator"` + `tabindex="0"` + `aria-valuemin/valuemax/valuenow`），
尺寸都存 `localStorage`。横向那条有上限保护：**把追问区拉到最高时，「发送给 Agent」仍然完整可见**
（实测 900px 视口下拖到 562px，按钮仍在视野内）。

窄屏（≤1100px）自动变单栏：两条分隔条都隐藏，上区不再独立滚动，回到原来的整列布局，
也不会留下按窄屏夹取过的尺寸值。

### 折叠说明

三段"读一次就够"的说明**默认收起**（文案一字未改，只是折叠）：
「如何处理这句话」「两种执行方式的区别」「关于「一次提示」」。点标题展开。

### 追问输入

- **纵向布局**：输入框占满整行，按钮与提示在下面一行。左栏只有 400px 宽，这样比并排多约 15% 宽度。
- 输入框随内容长高：1 行（48px）起步，最高 240px，再长就自己滚动。
- **发送键与上方主输入框统一：`Ctrl` / `Cmd` + `Enter` 发送，`Enter` 换行。**
- **追问同样带上左侧选中的「执行方式」。** 这一点曾经漏传过：接口在不传 `exec_mode` 时缺省走 `cluster`，
  于是「页面选了本地引擎、却在追问框里发起清洗」会实际起一个集群任务（本机没装 Hadoop 会当场失败）。
  现在除了传参，只要追问真的又发起了一次任务，对话里会写明**后端回显的真实口径**
  （取 `opts.exec_mode`，而不是页面上选中的值 —— 两者可能不同）。
- 追问区**高度可拖**（见上），对话自己滚动、输入框贴在底部；对话至少保留 96px，
  输入框长高不会把对话挤没。

### 大模型 API 接入（可选，入口常显）

顶栏右上角有一个「**API**」入口，**无论后端是否开启它都在**。点开是一个**居中弹窗**：

| 项 | 做法 |
|---|---|
| 形态 | 居中弹窗（`max-width: 560px`），**不是**抽屉、也不是把正文推下去的横条 |
| 背景 | 深色遮罩 + `backdrop-filter: blur(2px)` —— 后方主页面被压暗并虚化 |
| 关闭 | 右上角 **×**（48×48 热区、内联 SVG）、遮罩点击、`Esc` 三种方式 |
| 分层 | Carbon 的 Overlay 阴影 `0 2px 6px rgba(0,0,0,.3)` + 0 圆角。Carbon 契约里阴影**专给浮层**（dropdown / tooltip / modal），此处合规 |
| 动效 | 进入 240ms（craft 规定浮层 200–300ms）；`prefers-reduced-motion` 时不动画 |
| 无障碍 | `role="dialog"` + `aria-modal="true"`；打开即锁 body 滚动；**焦点陷阱**（Tab 在内循环，`Esc`/× 才解除）；关闭后焦点还给入口按钮 |

**为什么入口常显**：后端没开总开关时，弹窗里会放一条黄色提示如实说明
（「后端未开启大模型增强：启动时**请**设置 `AGENT_LLM_SUPPORTED=1`」）并把表单整体置灰。
把入口藏起来会让这个功能**不可发现** —— 连组长都找不到。

| 后端启动前 | `/health` 的 `llm.supported` | 弹窗里 |
|---|---|---|
| 什么都不设（默认） | `false` | 黄色提示 + 表单置灰不可填 |
| `export AGENT_LLM_SUPPORTED=1` | `true` | 正常可填 |

弹窗里填：接口地址（OpenAI 兼容，填到 `/v1` 即可）、API Key、模型名，以及**「什么时候用它」**：
`fallback`（默认，只有规则彻底听不懂才问）/ `always`（每句都问）。

三条纪律：

1. **配置只写本机 `localStorage`**，不写任何仓库文件，后端也不落盘（随每次请求带 `body.llm`）。
2. **它只做两件事**：把话理解成一次工具调用、把结果说明说得更顺。**不生成清洗规则、不产出任何数字。**
3. **连不上自动回落规则解析**，功能不降级 —— 「测试连接」可以单独自检。

## 5. 四条不会被违反的规矩

1. **不编造**：任务未成功时，结果区**一个数字都不显示**，只显示状态与失败原因。
   接口返回 `TASK_NOT_FINISHED` 时页面继续显示进度，绝不拿上一轮旧数字顶替。
   「评价局限」原样展示后端返回的内容，不删改、不解释。
2. **隔离 ≠ 修复**：「清洗结果」页顶部常驻提示条，说明被隔离的记录是**移出正表**而不是被修好；
   五维分数与数据量变化始终同屏。
3. **配置只读**：规则、阈值、指标、权重全部来自 `config/*.json` 与接口返回；
   前端不硬编码任何领域规则。指标名也是从评分方案里查出来的。
4. **大模型不碰数字**：它只负责「把话理解成一次工具调用」和「把说明说得更顺」。
   分数、行数、隔离数一律来自 Hadoop 的真实运行；它既不生成清洗规则也不产出数字，
   连不上就自动回落到规则解析。

## 6. 抽样警戒

页面会自动核对输入行数：`counts.input.ratings_lines` 等于全量基准 **1,150,241** 时显示绿色「全量运行」，
否则挂**黄色持久横幅**提示「样本 · 非全量」。这条是为了防止把样本数字当成正式结果。

自第 4 节的 **D-016** 起，driver 的默认口径已翻转为 `full`（全量）：页面发起的任务不传 `--scope` 即全量，
样本口径只能显式加 `--scope sample`（评分表前 2000 行，仅联调用）。

## 7. 已知限制（如实说明）

| # | 限制 | 说明 |
|---|---|---|
| 1 | **没有取消按钮** | driver 与 Agent 都没有提供取消任务的接口。因此页面不画一个点了没用的按钮，改为明确显示进度、已用时，并在超过 1 分钟后提示全量任务通常需要 8–10 分钟。 |
| 2 | **「本地引擎」不是正式口径** | 它用同一套引擎在本地跑完清洗与评分，自第 4 节的 **D-015** 起**不再依赖 HDFS**（`publish()` 在非集群模式下是 no-op，`paths.published_dir` 为 `null`），因此在没有 Hadoop 的机器上也能成功。但课程要求「清洗与评分必须由 Hadoop 实际执行」，正式数字必须来自「Hadoop 集群」模式 —— 页面依据**结果自带**的 `published_dir` 判断执行环境，用**黄色横幅**（本地引擎）或**绿色横幅**（Hadoop 集群）明确区分。 |
| 3 | **`rule_notes` 是文档外的字段** | 结果里带「口径差异说明」，但接口文档 §4.5 的示例没有它。前端做成「有就显示、没有就说明本次没有」，不假设它一定存在。 |
| 4 | **字体回落** | 设计契约指定 IBM Plex，本机通常未安装；离线环境不允许 CDN 字体，因此按契约声明的回退链落到 `Segoe UI / Microsoft YaHei`。中文由系统字体渲染。 |
| 5 | **中文行高与契约的拉丁值不同** | 契约的行高是拉丁口径（正文 1.5 / 标题 1.17）。中文必须用 1.7 / 1.35，否则多行中文会上下相碰。这是 craft 规则里明确要求的 CJK 覆盖，已在 `app.css` 顶部注明。 |
| 6 | **新口径 `scope` 前端读不到** | 第 4 节的 **D-016** 起 driver 支持 `--scope full\|sample`（**默认 `full`**，全量为正式口径），口径写入 `status.json.scope`；但 `status` 命令返回的信封是一串**写死的字段清单**，里面没有 `scope`，`result` 信封里也没有。所以前端目前仍只能用 `counts.input.ratings_lines` 反推行数判断是否抽样（接口文档 §4.3 也承认两条路都行）。另外**页面没有数据范围选择器** —— `/api/chat` 只接受 `text / task_id / auto_start / exec_mode`，传不了 `--scope`；想跑样本口径目前只能在命令行显式加 `--scope sample`。 |
| 7 | **上区会独立滚动** | 左栏重构为三段后，上区（对 Agent 说 + 执行情况）自己滚动、主操作常驻、追问区高度可拖且永远可见。代价是**「执行情况」默认在上区的折叠线以下** —— 已用「发起任务后自动滚到执行情况」缓解。窄屏（≤1100px）回到整列布局，不再独立滚动。 |

## 8. 设计契约

界面遵循 Open Design 设计系统 **`ibm`（IBM Carbon 风格）**，关键约束逐条落实在 `css/app.css`：

- 0 圆角（按钮 / 输入框 / 卡片）；24px 胶囊只用于 tag
- 卡片无边框、无阴影，层次靠背景色分层
- 唯一强调色 Blue 60 `#0f62fe`，同屏可见使用不超过 2 处
- 输入框只有 2px 底边框，不做四周描边
- 8px 栅格；字重仅 300 / 400 / 600
- 禁用渐变、装饰性阴影、emoji 图标

图表颜色单独一套（清洗前 = 中性灰，清洗后 = 语义绿），不占用强调色配额。

### 文案规则（网页不是 PPT）

三条硬规则，加新视图时照做：

1. **空态只说「下一步做什么」，全页只留一处。** 卡片空位就是一个 `—` ——
   卡片标题已经说明了它是什么，不再逐卡写「任务成功后这里会显示…」。
2. **标题不解释、不带括号。** 口径说明属于「评分依据」页或文档，不属于标题。
3. **界面上不出现「汇报 / 演示 / 正式口径」，也不写「我们不硬编码」。**
   文案的**主语只能是数据或用户要做的事**，不能是实现或合规。

先问一句：**用户此刻要做什么决定？** 答不出来的字，删掉或折叠。

> 反例（都曾真实出现在页面上，已清掉）：
> `数字不可用于汇报` · `汇报现场演示用这个` · `前端不硬编码任何规则` ·
> `本页不显示任何分数` · `其它区块不受影响` · `否则分数不可比`
